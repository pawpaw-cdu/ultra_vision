# Ultra_Vision 优化方向

> 依据：① 本项目 2026-10-09 ~ 10-11 的实车与离线经验；② sp_vision_25 的技术实现
> （`sp_vision_25_技术分析报告.md`，其 §11 专门做了与本仓库的逐项对比）；
> ③ 本轮"用已有实车数据对账"新拿到的几组数字。
>
> 本文只谈**方向与验收**，每一条都给出证据出处与验收口径。

---

## 0. 一句话结论

**把力气按这个顺序花：**

1. **底盘构造 / 重投影**（最大误差源，同一份数据差 20 倍）——只留**一个**模型定义，
   并用离线重投影指标做回归门；
2. **局部拟合器**——它已经不是"能不能出解"的问题（本体已验证），而是**定位**问题：
   把它当"正面观测的 ω/yaw 观测源 + 旋转中心观测源"，而不是"高速跟板增强"；
3. **时间基与识别层偏置**（识别层 0.12~0.16 m 是整条误差链的源头）；
4. **决策层补"瞄准旋转中心"档**（用拟合器的 C 与 ω，而不是追板）；
5. **工程可维护性**（tracker 4900 行 / 12 文件，隐藏耦合是最贵的成本）。

| 关联层 `nomatch` 占检测比 | **39~46%** | — | 同上 |

两条推论：

- **滤波器数学不是瓶颈**（状态/观测方程本来就是照 sp_vision 抄的，ω 在 2~5 rad/s 只有
  1~2% 误差）；瓶颈全在**模型构造**与**观测来源**。
- **慢转（≤0.5 rad/s）时 ω 不可观测**（52.6% 误差）——这不是 bug，是 sp_vision 报告
  §7.4 讲清楚的事实：`w` 必须"看到旋转"才可观测。它同时说明：**拟合器在慢转时也救不了
  ω**（弧段覆盖的相位不够），它的价值区间是"中速 + 正面"。

## 2. 方向 A（P0）：底盘构造与重投影只留一个定义

### 2.1 为什么这是第一优先

同一份数据、同一个指标，我们 74 px、spv 底座 3.4 px。**这不是"精度差一点"，是
"模型不在观测上"**。它会同时污染：选板、中心估计、提前量、以及所有基于重投影的门控
——也就是说，**上层任何改进都会被它吃掉**。

### 2.2 已经定位到的具体病灶（都有实车证据）

| 病灶 | 证据 |
|---|---|
| `geometry_learn` 在实车会漂 | 18 s 内 `l` 从 +3.5 cm 走到 −16 cm，撞到两端钳位（`docs/spv_port.md`） |
| `hard_plate_constraint` 一关，模型没有任何东西钉在观测上 | 同上 |
| `updateChassisFromFit` **零调用点** | 慢层 R/α/h 从来没写回模型（审计 F 项，已在 `da03fc4` 修复） |
| 被钉住的那块板 yaw 一偏，构造误差就不可接受 | 实车观察；根因是"选一块板构造整车" |
| 四块板高度不统一 / 前后透视反了 | 实车观察；根因是"世界系/相机系混用" |
| 关键点相对真值板心 ~29 px 系统偏置、真值↔观测时间基不一致 | 上游排查记录 |

### 2.3 sp_vision 是怎么做的（可直接借鉴的部分）

1. **单一几何函数**：`h_armor_xyz(x, id)` 一处定义"板心 = 车心 ± r·(cosφ, sinφ) + 高度"，
   重投影、居中、瞄准全走它；
2. **`r/l/h` 是"近常数"状态**：过程噪声极小、**硬边界 ±5 cm**，不搞在线几何学习；
3. **模型不依赖"选哪块板"**：任意一块板的观测都能反推车心（YPD 直接给板心，板号只影响 φ）；
4. **PnP + 暴力 yaw 搜索**（140°/1° 步长）保证正面观测时 yaw 不至于病态。

> 注：本仓库其实已经有一个"重做版"单一入口 `common/chassis_model.hpp`
> （`chassisArmorPose(center, yaw, geometry, plate)`，文件头就写了"坐标系铁律：只在世界系里
> 算模型，要画到图上由调用方统一变换"）。方向 A 的重点因此不是"再写一个"，而是
> **① 核实所有消费者真的都走它；② 给它配一条回归门。**

### 2.4 建议动作

| 编号 | 动作 | 验收 |
|---|---|---|
| A1 | 画依赖图，把"自己拼板心 / 自己算重投影"的调用点全部收敛到 `chassisArmorPose` | `rg` 无旁路；`tools/dep_lint.sh` 加一条 |
| A2 | `l/h` 从"可学习"降级为"±5 cm 硬界的慢状态"，并给它们**显式观测量**（板心高度差 ⇒ 图像 v 坐标差），否则永远不可观测 | 实车 18 s 录制里 `l/h` 不撞界、中心误差不劣化 |
| A3 | **重投影回归门**：固定一份实车检测流，`spv_replay` / `replay_obs_csv` 输出"检测↔模型板心"中位与 p90，写进 CI | 中位 < 5 px（当前 spv 3.4、我们 74） |
| A4 | **决策点**：是把 `src/spv` 提升为唯一生产底座，还是把 spv 的简化**反向移植**进现有 tracker？ | 见 §6.1 |

> **为什么 A3 要放在 A1/A2 前面**：它只要 1 天，而且它把"模型好不好"从靠肉眼看画面争论
> 的问题，变成一个有数字的门。本轮所有发现（`R_cv` 转置、深度门控、弧段混板）都是靠
> 这类离线指标才定位到的。

## 3. 方向 B（P0/P1）：局部拟合器的定位与收口

### 3.1 本轮确立的能力边界

| 结论 | 证据 |
|---|---|
| 模型本体是对的（含 15° α、双灯条、刚体旋转） | 合成自检 rmse **0.055 px**、ω 误差 0.4% |
| **前提是"单板弧"**：一条窗口里混进多块板 → 非凸、解不可靠 | 窗口 trace 拍到一条"弧"混 **9 段板**；旧口径有效 21%、rmse 195 px |
| 分弧后有效 82%、rmse 中位 11 px，静止 ω≈0、自旋落 [0, 5.8] | 同一份数据 A/B |
| **`plate_yaw_offsets`（逐条板号）在分弧后是恒等变换** | 开关两次跑出**逐位相同**结果（2138/1748/11.15） |
| **跨板弧不可靠**（非凸，快层可能落坏解） | 合成 S2：有时 0.9 px、有时 34 px |
| 拟合器要求：正确的 `R_cv` 约定、参数上下界、`h` 先验、按实车距离设的深度门控 | 三处移植 bug 的实测 |

### 3.2 定位（与上一轮的价值评估一致）

不要在"高速跟板"上加码——**比赛里大部分小陀螺是 2~4 rad/s，而且 5 rad/s 以上主流方案
本来就不跟板**。拟合器真正不可替代的是两件事：

1. **正面观测时的 ω/yaw 观测源**：单帧 PnP 在正面时 yaw 病态，而弧段解没有这个问题；
2. **旋转中心观测源**：`C` 与 `drift` 可以直接喂"瞄准旋转中心"那一档（见方向 D）。

### 3.3 建议动作

| 编号 | 动作 | 验收 |
|---|---|---|
| B1 | **立刻**：把 `local_fit.min_depth` 从默认 `1.5` 调到 `0.8`（实车靶在 1.2~1.6 m；这条在 sp 端口上直接造成 `attempts=0`） | 实车录制里 `push>0 && fit>0` |
| B2 | 拟合器内部：`θ0` 的界做成**镜像不变**（或在多起点里加镜像起点并回正 ω），否则同一份数据镜像口径 rmse 差 2 倍（11.2 vs 5.98 px） | 两个镜像口径的 rmse 中位一致 |
| B3 | 注入门控：只在"弧内单板 + 相位跨度 ∈ [30°, 120°] + rmse 过门限"时注入；否则只记录 | 静止段 ω 注入后 EKF 的 ω 不跳 |
| B4 | 两个标定项（`yaw_rate_sign`、`yaw_offset`）上机各做一次**已知方向小陀螺**定死；并加在线自检（静止时 \|ω\| < 0.2） | 自检通过 |
| B5 | 慢层几何（R/α/h）只在"同帧多板"或"长时间弧段"时更新，且必须先过 A3 的回归门 | `geometry=` 计数与模型指标同时改善 |
| B6 | 删掉没有实证收益的开关（本轮实测 `center_anchor` 是唯一让模型变差的开关：7.79→11.88 px），保留的每个开关都要有一行 A/B 记录 | 配置项数量下降、每个都有出处 |

## 4. 方向 C（P1）：时间基与识别层偏置

**证据**：识别层 `observation error` 中位 0.12~0.16 m（整条链里最大）、关联层 `nomatch`
39~46%、关键点相对真值板心 ~29 px 系统偏置、真值↔观测时间基不一致。

sp_vision 在这件事上**并不比我们好**（其报告 §12.4 待确认项 1 明确写了：相机时间戳用的是
"取到帧缓冲后"的 `steady_clock::now()`，没用 SDK 曝光时间戳；它对 IMU 用 `imu_at(t - 1ms)`
做对齐）。所以这是**我们自己要领先的地方**，而不是照抄项：

| 编号 | 动作 | 验收 |
|---|---|---|
| C1 | 相机改用 **SDK 曝光时间戳** + 常数传输延迟（延迟作为可标定量） | 静止靶、已知距离下模型板心↔检测板心残差中位进一步下降 |
| C2 | IMU 四元数按曝光时刻**插值**取（而不是"取最近帧"） | 云台快速转动时重投影残差不随角速度增大 |
| C3 | 关键点偏置标定：把 ~29 px 的系统偏置量出来（已知距离/角度的靶板），固化成补偿或改进关键点回归 | 偏置 < 5 px |
| C4 | 把 IMU 四元数录进检测流（`real_runner` 已有 `io::ImuSample`），这样 sp 底座能被喂**和真机同一个观测**，A/B 才真正公平 | `spv_replay` 支持 `--imu` |

## 5. 方向 D（P1）：决策层补"瞄准旋转中心"

**证据**：`layer_error_budget.md` 里 `chassis center error` 0.18~0.29 m、`aim_settled`
65~95%；更重要的是"用差分放大 Yaw 信号"的做法会把 EKF 的**平滑滞后**放大成 ∝ω 的偏差
（实测 ω=4.5 时约 13°）。

| 编号 | 动作 | 验收 |
|---|---|---|
| D1 | 决策档位补一档"守角/瞄中心"：目标 \|ω\| 超阈值或正面不可观测时，直接瞄**拟合器给的旋转中心 C** | 仿真 5 rad/s 的 `in_fire_window` 与 \|yaw_err\| 不劣于现状（现基线 100% / 0.59°） |
| D2 | 开火判据改成"预测射击轨迹与**板轨迹（含 ω）**的交点"，而不是"当前板位置" | 同上 |
| D3 | 可选：评估 sp_vision 的 MPC（TinyMPC，100 步/1 s、三阶串口）替代分档决策 | 同一仿真批次 4 档转速全面对比 |

## 6. 方向 E（P2）：工程可维护性（"隐藏问题太多"的根治）

- 现实：`src/auto_aim/Kalman/` 12 个文件、**4900 行**，其中 `tracker.hpp` 829 行、
  `armor_ekf.hpp` 1128 行；一个 `Tracker` 同时管状态机、关联、几何、慢层、拟合器回调、
  看门狗。**"改一处不知道会动哪里"本身就是最大的成本。**
- sp_vision 的对照：一个 11 维 EKF + 一个 tracker，逻辑量约为我们的 1/4，代价是它丢了
  我们有的东西（见 §7）。

| 编号 | 动作 |
|---|---|
| E1 | 明确三个接口契约：**观测入口**（谁能写 EKF）、**几何来源**（唯一 `chassisArmorPose`）、**慢层写回**（谁在什么时候改模型）。三者之外的代码不许碰模型 |
| E2 | 把 `src/spv` 当**参照实现**长期保留：任何模型改动都同时跑两套，指标一起看 |
| E3 | 离线 A/B 工具链固化成 CI：`replay_obs_csv --detections`、`spv_replay`、`local_fit_replay`、`local_fit_selftest` 四条，一条命令出表 |
| E4 | 真实入口继续按 `docs/real_entry_refactor_plan.md` 拆（`image_servo` 优先），但只在 NUC 上做、每步保持可上台架 |

### 6.1 决策点 A4：底座怎么选

| 方案 | 优点 | 代价 | 建议 |
|---|---|---|---|
| **① 切到 `src/spv` 当唯一底座** | 立刻拿到 3.4 px（本文最大单笔收益）；代码量小、逻辑清楚 | 丢掉 sin/cos 参数化、IESEKF、马氏关联、双模型、看门狗（需按 §7 逐个补回） | **推荐作为 P0 默认路径**：先切底座把误差压下来，再把我们的优点当作**可 A/B 的增量**一个个挂回去 |
| ② 反向移植 spv 的简化进现有 tracker | 不动上层 | 在 4900 行里做减法是高风险手术；本轮"改一处坏一处"的经历已说明成本 | 只在没时间切底座时用 |

## 7. 不要照搬 sp_vision 的地方

（来自其报告 §12.2/§12.3，以及本轮移植过程中亲自踩到的）

1. **NIS 阈值 0.711**：注释写"χ²(4, 95%)"，实际 χ²(4,0.95) = **9.49**；而且它的统计量是在
   **更新之后**用更新后的 P 与残差算的（不是标准新息统计），两个"错"互相抵消。**不要搬
   数字**，要用就用标准新息 + 标准卡方门限。
2. **`Target::update` 固定循环 3 次**，而 `armor_xyza_list()` 长度是 `armor_num_`：
   `armor_num_ == 2`（平衡步兵）时 **vector 越界（UB）**。
3. **无观测拒绝**：任何观测无条件进 EKF，只能靠事后看门狗置 lost。
4. **决策不检查 `convergened()`**：刚重捕时未收敛的 ω 直接进提前量。
5. **`Solver::optimize_yaw` 是 140 次重投影的暴力搜索**（成本）；`SJTU_cost`、
   `oupost_reprojection_error` 是死代码。
6. **每类各自 `YAML::LoadFile`、没有默认值与校验**：`configs/example.yaml` 因此**不可运行**。
7. **`tools/thread_pool.hpp` 反向 include `tasks/auto_aim/`**，层次成环。
8. **移植过程中新踩到的坑**（sp_vision 原版也有）：神经网络构造函数**只填 `points`，
   `left/right` 是空值**（拿它喂拟合器 = 喂四个 `(0,0)`，会"完美拟合"出一个中心在两百万米
   外的退化解）；`Tracker::track()` **忽略 `use_enemy_color` 参数**；三处 `imshow` 没开关
   （无显示环境下直接崩 GTK）；vendored SDK 的 RUNPATH 会盖住系统 GenTL 插件。

## 8. 落地顺序（每步都有可验收的判据）

| 顺序 | 任务 | 成本 | 验收判据 |
|---|---|---|---|
| 1 | **A3 重投影回归门**（离线指标进 CI） | 1 天 | 一条命令出"检测↔模型板心 中位/p90" |
| 2 | **B1 深度门控**（`min_depth` 1.5→0.8） + **A4 底座决策** | 半天 | 实车录制 `fit>0`；底座选定 |
| 3 | **A1/A2 模型单一定义 + `l/h` 降级** | 3~5 天 | 中位 < 5 px；`l/h` 不撞界 |
| 4 | **B2/B3/B4 拟合器收口与标定** | 2~3 天 | 静止 ω≈0；镜像口径一致；标定项定死 |
| 5 | **C1/C2 时间基**（曝光时间戳 + IMU 插值） | 2~3 天 | 残差不随角速度增大 |
| 6 | **D1/D2 瞄中心档 + 开火判据** | 3~5 天 | 5 rad/s 的 `in_fire_window` 与 \|yaw_err\| 不劣化 |
| 7 | **E1~E3 契约与 CI** | 贯穿 | 配置项数量、指标表稳定 |

## 9. 附录：本文数字的复现命令

```bash

./build_sim/replay_obs_csv --detections /tmp/det2.csv --config-dir configs \
    --local-fit --local-fit-period 4            # → 中位 74.05 px / p90 140.86
SPV_LIGHTBAR_LEN=0.060 SPV_SMALL_ARMOR_WIDTH=0.1315 \
    ./build_sim/spv_replay --detections /tmp/det2.csv --out /tmp/spv.csv
                                                # → 中位 3.40 px / p90 357.9

# ② 局部拟合器本体（合成真值回灌，隔离数据关联）
cd sp_vision_25
cmake --build build --target local_fit_selftest
./build/local_fit_selftest /tmp/local_fit_replay.yaml 0.1158 -0.227
                                                # → S1 rmse 0.055px / ω=3.011

# ③ 局部拟合器在实车检测流上的 A/B（弧段切分 vs 一条缓冲）
LOCAL_FIT_LOG=/tmp/fit.csv ./build/local_fit_replay \
    --detections /tmp/det2.csv --uv-camera ../Ultra_Vision/configs/camera.yaml

# ④ 分层误差预算（仿真 4 档转速）
tools/auto_aim_sim_test.sh --no-build --seconds 10 --camera armor_camera_far \
    --gyro 1 --gyro-speed 5 --out /tmp/layer_sweep/sp5
```
