# 能量机关链路对照：深大 RP-26Rune vs Ultra_Vision energy/

> 目的：把"跟着感觉调参"换成"对着差异改结构"。
> 所有结论都标注了出处（对方仓库 `RP-26Rune-main`、我们 `src/auto_buff/`）和本机实测数据。
> 状态：2026-09-23，基于 `models/openvino/RuneDetectionModel-master/model/model-0624.onnx`（五点模型）。

## 0. 一句话结论

深大把**网络关键点只当"语义种子"**：真正的几何来自
「颜色差轮廓 → 语义分割 → 距离场(chamfer)拟合 → 跨帧平面拟合」，
相位来自「平面内 靶心−圆心 向量」，
火控是「开火许可 + 冷却 + 换靶重置」。

我们目前是「关键点 → 直接 PnP → 多状态 EKF → 固定间隔开火」，
于是**关键点 1~2 px 的噪声被直接放大成相位/深度/朝向的抖动**，
云台被带着摆，符被摆出画面 —— 这是当前所有"打不中/不激活"现象的共同源头。

## 3. 关键差异（差异 → 后果 → 证据 → 建议）

| # | 差异 | 后果（本机实测） | 建议 |
|---|---|---|---|
| 1 | **几何来源**：他们=轮廓+距离场+平面窗口；我们=原始关键点 PnP | 关键点 1~2 px 噪声直接进入姿态：IPPE 双解逐帧翻转、圆心投影偏差、`EKF 的 yaw` 跑到 30°+；实测有检测帧只占 17~38%，符常被摆到画面边缘 | 做"最小版轮廓精修"：ROI 内 R−B 二值化 → 取装甲板/灯臂轮廓 → 用轮廓 PCA 的 4 角替代网络关键点做 PnP（先只替换 anchor，不动其它） |
| 2 | **平面/圆心无时间记忆**（他们跨帧拟合平面并投影） | 我们的距离中位误差离线 +1.7%，但实车逐帧跳（p90 7.3 m） | 加世界系"圆心+法向"的滑动窗口拟合（EMA 或最小二乘），输出给 EKF 的 R_dis |
| 3 | **相位定义**：他们=平面内 (靶心−圆心) 向量角；我们=PnP roll | 靶面在 6 m 只有 ~28 px，姿态 1 px≈4°：roll 逐帧 ±5~8°，云台跟着抖 | 相位测量改为"用 R 标与靶心的向量角"（我们有 k2，可直接算），EKF 只留相位/角速度 |
| 4 | **小符运动模型**：他们 1 维卡尔曼 + 规则定速 1.0472 rad/s；我们 ω 是状态且几乎无过程噪声 | ω 靠观测微调，抖动被抓进相位 | 小符固定 ω=π/3；相位单独 1 维滤波（保留 EKF 也行，但要给 ω 过程噪声/或直接固定） |
| 5 | **换靶语义**：他们 0.30 rad(17°) 判换靶并**重置冷却**；我们 25°(0.35 slot) 判换轮且冷却独立 | 新靶亮起后可能仍在旧冷却里，白丢窗口 | 对齐阈值到 0.30 rad，并在"确认换靶"时重置开火节流 |
| 6 | **类别用法**：他们保留"已击打"类作为观测，只有位姿用未激活；我们直接过滤非 class0 | 网络若把点亮片判成别类，我们直接丢目标 | 保留全部候选进入几何/状态；只在"选择射击目标"时偏好未激活 |
| 7 | **旧数据兜底**：他们 0.2 s 后瞄符心；我们 coast + 回中位姿 | 丢帧期云台停在旧点，符更容易出画面 | 加"瞄符心"兜底（用平面圆心 + 已知半径） |
| 8 | **开火节流**：他们短连发(0.04 s)+0.7 s 冷却；我们固定 0.45 s 间隔 + gate_fire | 旧模型实测：gate on 30 s 只 6 发/0 激活，gate off 12 发/1 激活 | 保留 gate，但语义改成"换靶后立即放开、命中后进入冷却"，而不是整轮压制 |
| 9 | **贴边剔除**：他们有轮廓贴边判据；我们没有 | 网络在画面边缘给高置信度假点（实测 hint 偏出 90 px） | 候选中心/关键点距边界 <3 px 直接弃 |
| 10 | **弹道**：他们有阻力/马格努斯拦截解 | 仿真 25 m/s、6 m 下抛物线误差很小 | 暂不动，优先级最低 |

## 4. 已做改动里"需要复核"的部分（不要当成已验证结论）

下面这些是这两轮里为了定位问题加的，**证据强度不同**，后续要么补数据、要么回退：

- `input_scale: 0.00392`（归一化 0~1）：**强证据**（深大适配器一致 + 本机 k2 误差 0.4~0.7 px、靶面半径 13.8 px≈真值），保留。
- `plate_point_order: "0,1,4,3"`：**强证据**（PnP 圆心反投影落在 R 标 7~8 px；换一位偏 90 px），保留。
- `require_inactive_class`：**待复核**。深大是"保留激活类做观测"，我们直接过滤。建议按差异 #6 重构。
- `min_plate_radius_px`、`min_/max_distance_m`、`hub_brightness_margin`、R 标 hint 合理性区间：都是**兜底闸门**，证据是"退化框/离域假点"，保留但应配合差异 #9 一起验证。
- `fire_gap_time 0.7→0.45`、`gate_fire true→false`：**证据不足**，属于试出来的值；建议按差异 #8 重做开火语义后再定。
- 亮点判据的小窗/大窗尺寸、`plate_radius` 计算：**证据不足**，先冻结，等 #1 的轮廓精修落地后再调。

## 5. 后续怎么干活（先看曲线，再改代码）

每次改动前先取这三条曲线，改完对比，不看单次 `activations` 下结论：

1. **可用性曲线**：每帧 `status`（TRACK/TEMP_LOST/LOST）+ 是否有候选 → 目标可用占空比。
   - 现状：实机闭环里"有检测"只占 17~38%；离线静态机位 91%。差距=云台被摆走。
2. **相位误差曲线**：`图像相位(靶心相对 k2)` vs `EKF 使用的相位` 的差（需要埋点，见下）。
   - 现状：`cmd−obs` 标准差 ~10.7°，单帧跳变 p90 11°，而开火判据 `fire_thresh=1.5°` → 几乎开不出火。
3. **每轮命中率**：sim.log 的"轮次 vs scored"序列（本轮实测 54%，基线 67%；**要激活需要连续 5 轮**，p=0.54 时成功率 ~5%）。

建议先加的**埋点（不改算法）**：
- CSV 增加：`aim_phase_deg`（靶心相对 k2 的图像相位）、`ekf_roll_deg`、`plate_r_px`、`hub_px`、`cand_n`、`cand_bright_max`；
- `tools/` 里加一个画曲线的小脚本，直接对这四列出图；
- sim 侧用 `--record-frames --record-stride N`，把"点亮片在哪、我们瞄哪"叠在图上抽查。

## 8. 逐步引入记录（每步都先建曲线、再看数据）

### 第 1 步：相位观测换成"平面内 圆心→靶心 向量角"（差异 #3）

改动：
- `rune_solver.cpp`：姿态解算后额外算 `phase_rad`（深大 `complete_candidate_target`
  的同构形式，基向量 u=+Z、v=(sin yaw, −cos yaw, 0)）；
- `rune_target.cpp`：measurement 1 的 roll 分量改用 `phase_rad`（PnP roll 兜底）；
- CSV 新增 `obs_phase_deg / pnp_roll_deg / sim_t / best_cls_score` 四列。

**实测结论：这条不是瓶颈，但它把误差来源彻底照亮了。**（同一批 168 帧同时有四个量）

| 对比 | std | p90 |
|---|---|---|
| PnP roll − 几何相位 | **0.4°** | 0.7° |
| EKF roll − 几何相位 | 2.6° | 5.0° |

即：PnP 的 roll 与几何相位几乎等价（**之前"roll 噪声 ±5~8°"的判断是错的**，
那次是把"图像相位"和"世界相位"两个不同参考系混在一起比，得出的假象）。
EKF 相对几何相位只差 2.6°，可以接受。改动保留（结构上更贴合参考实现、并且给了我们相位埋点）。

### 误差预算（同一轮 30 s，新模型）

| 项 | 实测 | 与基线对比 |
|---|---|---|
| 观测距离 | 中位 6.07~6.34 m（真值 6.05，+0.4%~+4.8%） | 基线 +2.8%~+8.9% |
| 靶面点半径 | 13.5 px（真值 13.6 px） | — |
| 有目标占空比 | 26~40% | **基线 26~39%，同级** |
| TRACK 占空比 | 67~78% | 基线 63~72% |
| 瞄准平滑度 `|Δaim|` p90 | 1.8° | 基线 1.9~2.1° |
| 云台跟随误差 `|aim−sent|` p90 | 10.7°（>1.5° 占 42%） | 基线 12.5~16.6°（>1.5° 占 34~39%） |
| 每次命中的性质 | scored 19% / 重复打同片 57% / 打错槽位 24% | 基线 scored 16~20% / 重复 58~80% / 错槽 0~26% |
| **每轮命中率** | **30~38%（最长连续 2）** | 基线 **40~67%（两次都凑到连续 5）** |
| 每轮落在机关上的弹数 | ~2.1 | 基线 ~4 |
| "打在未点亮时段"的命中占比 | **48%** | 基线 18% |

**结论：几何、相位、可用性、瞄准平滑度都与基线同级；真正的差距是"每轮有效弹数"——
我们的弹有近一半是在本轮已经失败之后才落地（48% vs 18%），等于开火节奏偏晚。**

下一步（第 2 步）：对齐开火节奏（差异 #5+#8）——换靶瞬间重置开火节流、
命中/换靶后立刻允许补射、不要等到 0.7 s 节流走完才开始打；
验收标准：`rune_curve.py` 面板 4 出现连续 5 个 Y，且"打在未点亮时段"占比 <25%。

### 第 2 步：开火节奏对齐（差异 #5+#8）

改动：
- `rune_aimer.cpp`：换靶时不再"从零开始等一个 fire_gap_time"，而是把节流提前
  （`last_fire_time_ = now - fire_gap_time`），对应参考实现的换靶 `reset_cooldown()`；
- `rune_node.cpp`：`post_hit_hold` 的解禁条件从"像素位移 >25 px"改成
  **相位跳变 >0.30 rad**（参考实现的 `target_switch_threshold`）——符一直在转，
  按像素位移解禁与"是否换靶"无关，会白等 0.37 s。

实测（30 s × 2 轮，新模型）：

| 指标 | 第 2 步 | 基线 | 说明 |
|---|---|---|---|
| 开火次数（shoot 行） | 12~15 | 10~20 | 对齐 |
| 落在机关上的弹/轮 | 1.7~2.4 | 2.0~4.2 | 改善但仍偏少 |
| **落在"未点亮时段"的占比** | **25~28%** | 15~49% | **从 48% 降到 25~28%**（本步主要目标达成） |
| 每次落弹的命中率 | 13~15% | 16~20% | 同级 |
| 每轮命中率 | 22~36%（最长连续 2） | 40~67%（两次都连续 5） | 仍偏低 |

结论：开火时机的浪费明显减少（48%→25~28%），但每轮落在机关上的弹数仍只有基线的
一半左右 → 下一步应继续在"新一轮开头多打几发、并保证前几发就落在点亮片上"上做文章
（例如：感知到新靶后 ~0.2 s 内开出第一发；把 fire_gap 在新靶窗口内放宽到 ~0.35 s，
但保持命中后的冷却）。

### 第 3 步：只把"未激活"扇叶当目标 + 多扇叶几何修正 + 小符固定角速度

这一步来自现场观察："小符激活过程中，两片已激活扇叶中间出现未激活扇叶时云台会左右拉扯"。
改动：

1. `rune_detector.cpp`：候选按类别**严格**分流——
   - 只有 `class 0`（未激活）进入目标选择；没有未激活扇叶时本帧判为无目标（不再退回去打旧靶）；
   - **所有**扇叶（含已激活）都参与几何修正：每片给出"圆心→靶心"方向，圆心必在这些
     射线上，≥2 片时用最小二乘求交点当圆心（`[rune hub]`），比单片 R 标稳。
2. `rune_target.cpp`：小符角速度按规则**固定**为 ±π/3（深大 `expect_angular_velocity` 同义），
   不再从观测里估计 ω —— 相位预测只依赖"相位 + 常量转速"。
3. `tools/rune_curve.py`：新增"目标相位跳变（换靶）次数"和"逐帧 |Δaim_yaw|"两项指标，
   作为"云台左右拉扯"的验收量。

实测（30 s × 2）：

| 指标 | 本步 | 上一步 | 基线 |
|---|---|---|---|
| **目标相位跳变（换靶）** | **0 / 1 次** | 15 / 8 次 | 0 / 0 |
| 逐帧 \|Δaim_yaw\| p90 | 1.80° / 3.40° | 4.90° / 2.37° | 2.16° / 2.50° |
| 每轮命中 | 42% / 40% | 36% / 22% | 67% / 40% |
| 落在"未点亮时段"占比 | 0% / 14% | 28% / 25% | 15% / 49% |
| 有目标占空比 | 20.9% / 19.7% | 27~30% | 26~39% |

结论：
- **左右拉扯消除**（换靶跳变 15/8 → 0/1），云台目标角抖动降到与基线同级；
- 打空（落在未点亮时段）从 28% 降到 0~14%，优于基线两次；
- 代价是**有目标占空比降到 ~20%**（严格只要未激活片）——这是与基线的主要差距来源，
  下一步应在这里补：多片几何给出更稳的圆心/相位 → 允许更长的滑行（coast），
  以及"观测中断时瞄符心"的兜底（差异 #7）。

### 第 4 步：修"大角度甩飞 + 归位"（现场反馈）

现象：瞄准过程中相机莫名朝一侧大角度转，随后归位；目标片靠近瞄点时更容易出现。
逐帧数据（`sent_yaw` 从 −6.5° 单帧跳到 −23.5°，而观测几乎没变）定位到两处：

1. **临时丢帧时瞄准器还在按 60°/s 外推扇叶**：`TEMP_LOST` 期间 `cmd_yaw` 仍以
   ≈57°/s 前进，20 帧就能甩出 40°+，把符甩出画面后判 LOST 并归位。
   → 按参考实现加"观测寿命"：`aimer.observation_life_s = 0.2 s`，超时后
   `RuneAimer::aimCenter()` **改为瞄圆心**、不再外推扇叶、也不开火。
2. **EKF 的圆心偏航角速度 `x[1]` 被相位旋转污染**：圆心的方位角本应静止，但该状态
   会被"靶心在转"的观测残差推动，滑行时把圆心按 60°/s 外推——所以连"瞄圆心"的
   保底也在漂。
   → 在每个预测步之前把 `ekf_.x[1] = 0`（`rune_target.cpp` 的 `update` 与
   `coastOrInvalidate`），物理上即"圆心在世界系静止，只有相位在转"。

实测（30 s × 2）：

| 指标 | 本步 | 上一轮 | 基线 |
|---|---|---|---|
| **\|Δsent_yaw\|>15° 的帧数** | **0 / 0** | 5 / 2 | 3 / — |
| 最大单帧下发角变化 | **5.5° / 5.4°** | 47.8° / 42.6° | 16.5° |
| \|sent_yaw\| p90 | 6.7° / 6.1° | 44.6° / — | 16.5° |
| 逐帧 \|Δaim_yaw\| p90 | 2.86° / 2.21° | 4.75° / 4.54° | 2.16° |
| 每轮命中 | 45% / 50%（最长连续 3 / 4） | 36% / 30%（最长 1 / 2） | 67% / 40% |

结论：**大角度甩飞与归位消除**（指标 0，且优于基线），每轮命中率同时提升到 45~50%，
离"连续 5"只差一步。待查：run2 的观测距离整体偏大（中位 6.97 m / +15%，run1 只有
+2.5%），怀疑该轮网络关键点整体偏小（靶面点半径 12.4 px vs 通常 13.4 px），
需要结合 §5 的曲线继续定位。

### 第 5 步：丢掉"归位"，改成"停在最后已知符心"（现场提问）

问题：为什么丢目标要回标定位姿？——`recenter` 是基线的兜底（怕估计被野值带飞、
外加仿真里对齐一次"假定云台姿态"），但它会 `target.reset()`，把相位/几何全丢掉，
重新捕获要 0.5~1 s；而符心在世界系静止、小符转速还是已知常量，这些信息本来不该扔。
用户的思路（"继续跟一片转，运气好正好是下一片"）本质就是**不要放弃已建立的估计**。

改动（`rune_node.cpp`）：
- 丢目标时把相机**停在"最后已知符心"的云台角**（`park_on_center_max_age_s = 1.5 s` 内有效），
  估计器继续滑行；网络一报出未激活扇叶立刻接上；
- 只有"连最后已知符心都过期"（>1.5 s）才回标定位姿 + 重置，作为最后兜底；
- 汇总里新增 `parked frames` 便于观察。

实测：单轮 `parked frames = 212 / 170`（大量时间在"停住等下一片"而不是回中），
run1 每轮命中 50%、甩飞 0 次；但发现**新一轮的系统性偏差**：

| 现象 | run1 | run2 |
|---|---|---|
| 选中靶面点的半径（px） | 13.2 | **12.4** |
| 深度校正后的观测距离 | 6.29 m（+4.0%） | **7.06 m（+16.6%）** |
| 每轮命中 | 50% | 22% |

两者成反比（12.4/13.2 ≈ 0.94 ↔ 距离 +12%），指向同一个原因：
**相机俯仰变化时靶面被"透视压缩"，而我们的深度校正 `focal·0.7/像素偏移` 假设
靶面正视**，于是偏移被压缩多少、距离就被高估多少。下一步的修法：
用靶面四点构成的四边形估出压缩比（外侧-内侧点距 vs 左右点距），
把偏移除以该 cos 再算距离（等价于参考实现用完整位姿做深度）。

### 第 6 步：解决"模型观测 与 估计器 抢云台"（现场提问，跑了多轮定位）

多轮逐帧调试后，"云台随意乱动"定位到**两个不同的原因**，先后修掉：

**原因 1：观测被野值门丢掉，估计器用旧相位继续指挥**
典型三帧：丢帧期间估计器滑行到 `ekf_roll = 57.5° / 139.8° / 153.3°`，新观测回来时那片
已经在另一个槽位（相位差 70°/144°），但**这一帧的观测被野值门挡掉**（圆心/距离跳变超限），
瞄准继续用旧相位 → 云台朝旧槽位甩一下、下一帧才突然对齐。另外圆心估计本身也会跳
（实测 `hub (448,286) → (597,238)`，150 px ≈ 15°），形成"云台摆 → 换片 → 圆心跳 → 更摆"的
正反馈。
修法（观测优先 + 二次确认，`rune_target.cpp`）：
- 相位跳 >0.35 槽位、圆心跳变或距离跳变时，**不直接丢**，而是缓存一帧；
- 下一帧观测与它一致（相位差 <0.35 槽位、圆心跳变 <6°）→ 认定目标真的变了，
  **用观测重置估计器**（观测接管）；
- 圆心跳变门 20° → **8°**（圆心在世界系里是常量，15° 的假圆心必须挡掉）。

**原因 2：轨迹生成器对"目标角阶跃 + 前馈尖峰"欠阻尼振荡**
修掉原因 1 后仍有摆动，逐帧数据显示：目标角 `cmd` 平稳（10.3→4.5°），
而下发角 `sent` 在 **6↔38° 之间来回摆** —— 与估计器无关，是轨迹生成器被前馈尖峰推进
非线性区。修法（`rune_node.cpp`）：阶跃帧前馈清零 + 前馈速度包络限幅（200°/s）。

实测（小符，各 3 轮）：

| 指标 | 第 6 步后 | 第 5 步时 |
|---|---|---|
| \|Δsent_yaw\|>15° 的帧 | **0~2 次/轮** | 5 次/轮 |
| 最大单帧下发角变化 | **≤20°** | 47.8° |
| 观测接管次数 | 1~3 次/轮（第 6 步中途曾因"长丢帧即接管"误触发 100+ 次，已改） | — |
| 每轮命中 | 12~40%（run 间方差 ±15%） | 30~50% |

**教训（写进工作方式）**：单轮 30 s 的指标方差（每轮命中率 ±15%）已经大于单次改动
的效果，之后再改必须按 A/B 跑 ≥5 轮比中位数，而不是看单轮。

### 第 7 步：扇叶 ID（槽位）跟踪 + 延迟提前量 A/B

**扇叶 ID（现场反馈："没做扇叶 ID 匹配，会选到已激活扇叶；随机选片带来不稳定"）**
小符 5 片靶在自转方向间隔 72°，相位按固定转速走 → "本帧相位 − 上一帧相位"只在换片时
多出 k×72°。用它对槽位累加编号，得到相对 ID（`target_slot_id`），并维护"已激活集合"
（按**开火瞬间锁定的槽位**记账 —— 命中反馈有 0.25 s 飞行延迟，而仿真在命中瞬间就换靶）。
已加：
- 候选/开火闸门新增 `slot_already_hit`：锁定的槽位若已在"已激活"集合里，**绝不开火**
  （类别被误判成未激活时也不会去打旧靶）；
- CSV 新增 `slot_id`、`slot_activated_mask` 两列，用于量化"是否打到已激活槽位"。
效果仍需 A/B（≥5 轮）验证，暂不当成已收益。

**延迟提前量（现场建议："归中后重新锁到下一片时应加延迟提前量"）**
把"曝光时刻 + 推理后采样"（提前量含传输 3~10 ms + 排队 + 推理 40~55 ms）做成开关
`frame_time_from_exposure` 做 A/B（各 3 轮）：

| 时间基准 | 每轮命中(中位) | 瞄准 \|Δaim\| p90(中位) | 甩飞帧(中位) |
|---|---|---|---|
| true（含全部延迟） | 33% | 6.02° | 2 |
| **false（提前量稳定）** | 30% | **4.92°** | **0** |

结论：**物理完整 ≠ 实测更好** —— 推理耗时是变化的（40~55 ms），直接乘进提前量等于给云台
加噪声；默认保留稳定版（`false`）。要同时"准 + 稳"应改成**平滑后的延迟估计**（例如对该
延迟做 EMA/中位数），这是下一步可做的点。

### 第 8 步：平滑延迟的提前量（第 7 步结论的落地）+ 发现"配对 A/B"

改动：提前量改用**平滑后的"帧到瞄准"延迟**（EMA，α=0.2），而不是当帧瞬时值。
`RuneAimer::aim()/aimCenter()` 新增 `detection_age_override` 参数，由节点传入平滑值。

A/B（各 3 轮）：

| 变体 | 每轮命中 | aim \|Δaim\| p90(中位) | 甩飞帧(中位) |
|---|---|---|---|
| 曝光时刻 + **瞬时**延迟 | 30/22/30 | 6.02° | 2 |
| 到达时刻（不补传播延迟） | 30/22/30 | 5.05° | 0 |
| **曝光时刻 + 平滑延迟（当前默认）** | 30/22/30 | **4.78°** | **0** |

结论：平滑后既保留了传播延迟补偿、又消掉了推理耗时带来的抖动 → 现在是三者中最好的一档。

**附带发现（对后续测试方式很重要）**：三个变体的每轮命中序列**完全相同**（都是 30/22/30），
说明仿真的场景按 run 序号可复现 —— 只要两组用**相同的 run 序号**，就是"配对比较"，
方差远小于随机重跑。后续 A/B 应固定序号成对比较（`--out` 分别给两组），必要时再增加序号数。

### 第 9 步：扇叶 ID 闸门做配对 A/B —— 实测更差，先关掉（重要方法示例）

用第 8 步发现的"配对比较"（同一 run 序号）测第 7 步加的 `fire_block_on_hit_slot`：

| 配置 | run1 | run2 |
|---|---|---|
| ON（已激活槽位不开火） | 18% | 36% |
| **OFF** | **40%** | **40%** |

并且逐帧验证了原因：把我们记的 `slot_activated_mask` 与仿真遥测的 `activated=` 掩码对齐，
**已激活片数在 45~62% 的帧上不一致**（例：仿真 `00001` vs 我们 `00110`）——相对编号会漂
（相位步进在丢帧 >0.6 s 时出现 ±36° 歧义，且"命中记到开火槽位"也会错配）。

处理：闸门默认关闭（`fire_block_on_hit_slot: false`），但
- `slot_id` / `slot_activated_mask` 继续写进 CSV；
- `tools/rune_curve.py` 新增一行 **slot 记账一致** 指标（与遥测比对），
  这个数降下来之前不启用 ID 闸门。

**方法教训**：一个"看起来显然更好"的机制（ID 匹配防打旧靶）也可能因为实现精度不够而变差；
只有配对 A/B + 逐帧真值比对能看出来。ID 的正确定位是"先做准（可用来看/用来建模），
再用来做硬闸门"。

### 第 10 步：离线验证（先不跑闭环）——ID 算法与圆心的真值比对

按现场要求"先验证、先不跑整条链路"，把 ID 相关的东西都做成离线可校验的：

1. `tools/rune_id_check.py`：用一次 run 的 `vision.csv`（逐帧观测相位）+ `sim.log`
   （仿真真值 `highlighted` / `activated`）离线重放"单扇叶构建格点 + 新片匹配"，
   与"相位累加"版对照，输出**每个仿真模块号 → 我们槽位**的映射稳定性。
   当前结果：匹配版 46%、累加版 80%（`/tmp/rune_fb_on_1`）——**都还不够可靠，闸门保持关闭**。
2. `tools/rune_curve.py` 增加 **slot 记账一致** 指标（我们的已激活掩码 vs 仿真 `activated=`），
   当前 45~79% 不一致。
3. 圆心真值校验（同一批帧离线回放 + 模型输出逐帧对齐）：
   **我们的 `r_center` 与模型给出的 R 标中位偏差 0.3 px** —— 圆心是准的。
   （先前用"按索引猜帧"比出 82 px 的结论是**对齐错误**，已纠正。）
4. 用**原始录制帧**独立复测靶心转速：≈ −62 °/s，与仿真源码
   `ROTATION_BASELINE_SMALL = π/3`（60°/s）一致 —— 固定转速外推的前提成立。
   （管线里按整段拟合出的 −30 °/s 是把"换片跳变"混进拟合的假象，不作为结论。）

结论：**圆心与转速这两个前提是对的；不可靠的是"哪一片被我们锁定"**（目标选择）。
所以 ID 要真正可用，必须先让"锁定的是当前亮片"这件事稳定下来（等于把每轮命中率
从 ~40% 提上去），再谈用 ID 做闸门/建模。

### 第 11 步：把"可用性"拆开，修掉其中最大的一块（同帧离线对照）

一次录制 run（419 帧）按"仿真相位 × 是否有候选"分解：

| 情况 | 帧数 | 说明 |
|---|---|---|
| 机关没亮片（inactive/failed）+ 无候选 | 160 (38%) | **正常**，本来就没有目标 |
| 亮片期 + 有候选 | 148 (35%) | 正常检出 |
| **亮片期 + 无候选** | **105 (25%)** | 需要解释：亮片期检出率只有 58% |

再对这 105 帧逐帧跑网络看最高分类分：

| 网络最高分 | 帧数 | 结论 |
|---|---|---|
| **≥0.65（远超阈值）** | **29 (52%)** | **被我们自己的过滤挡掉**，不是模型问题 |
| ≈0（<0.1） | 17 (30%) | 网络什么都没看到 → 符不在画面（指向/FOV 问题） |
| 0.1~0.65 | 10 (18%) | 弱检出，阈值相关 |

闸门归因：这 29 帧全部落在**类别过滤**上（`cand_n` 统计点在类别过滤之后，所以表现为"无候选"）。
离线亮度比统计（38 帧存在非 class0 候选）：20 帧**压根没有 class0 候选**（应当采信）、
18 帧**有更亮的 class0**（不应采信）—— 也就是"类别优先 + 亮点裕度"这条规则的两个分支都判对了。

**同帧离线对照**（同一批录制帧，两种过滤策略只在代码里切换，不跑仿真）：

| 过滤策略 | 亮片期检出率 |
|---|---|
| 严格只要 class 0 | 50%（63/125） |
| **类别优先 + 亮点裕度 1.3** | **66%（83/125）** |

**方法教训（本轮最有价值的一条）**：`rune_ab.sh` 那种跑仿真的 A/B 受 ±15% 的 run 方差干扰，
而"**同一批录制帧上切换策略做离线对照**"是配对比较，噪声小得多、迭代快得多。
后续类似"过滤/阈值/几何"改动的验收都应优先用这种方式，只在需要闭环效应时才跑仿真 A/B。

剩余（下一步方向）：亮片期仍有 34% 未检出，其中约 30% 是"网络什么都没看到"——
即符不在画面里（指向/FOV），属于云台侧；另外 18% 是弱检出，属于阈值/尺度。

### 第 12 步：把 class 当"语义"而不是"过滤器"（现场提示）

现场提出：**"构建模型的那块装甲板才应该是 class 0"** —— 即
`class 0 = 未激活 = 当前该打的那片（也是格点模型的锚点）`，
`class 1/2 = 已经打过的片`，后者不应该被过滤掉，而应该用来
**更新"哪些槽位已激活"并校验格点模型**。

改动（`rune_detector` 暴露过滤前的候选、`rune_node` 按语义记账）：
- `RuneDetector::lastCandidates()`：保留**过滤前**的全部候选（类别 + 靶心位置）；
- 节点按"候选与当前目标的相位差 → 槽位偏移"把它们折算到 5 槽格点上，
  用类别直接标记**该槽位已激活**（不再只依赖命中反馈：命中反馈有 0.25 s 飞行
  延迟、且换靶时会记错片）；
- 因为模型类别会误判（23%），加**每槽 3 帧投票**才落账。

实测：

| 指标 | 改前 | 改后 |
|---|---|---|
| slot 记账与遥测不一致 | 65% / 79% | **44% / 55%** |
| 单帧下发角 >15° 的帧 | 1 / 0 | 0 / 1（最大 14.7° / 16.4°） |
| 每轮命中 | 50% / 50% | 36% / 42%（4 轮样本，仍在方差内） |

结论：投票确实压住了"亮片被误判成 class1 → 把该打的槽位记成已激活"的过计数
（65~79% → 44~55%），**但剩余不一致主要来自"我们的相对槽位编号 vs 仿真模块号"
的映射关系**，不是类别本身。所以 ID 闸门继续关闭；下一步是让格点锚定更稳
（用 class0 片作锚、只在真正复位时重锚），把一致性推到 >95% 再启用。
