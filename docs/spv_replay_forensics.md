# sp_vision 离线回放器：两个喂法 bug 与修正后的基线

> 2026-10-14。起因：按"只在静止档重做残差分解"这一步排查时，发现**回放器本身
> 把数据喂错了**。修完之后，"模型保真度只有 3.28px、任何观测都被 NIS 拒掉"
> 这个结论不成立——它是喂法造出来的。**此前所有用这个回放器做的 A/B（局部拟合器、
> UV-EKF）都建立在一个转错 ≈90° 的世界系上，结论需要重做。**

## 结论摘要

| 指标（静止档，单板被跟踪） | 修之前 | 修之后 |
|---|---|---|
| 模型重投影四边形的 长边/短边 | **4.66**（检测出来的是 2.44，真值 2.45） | **2.26** |
| 被跟踪板 四角点重投影 RMSE | 87.9 px | **11.4 px** |
| 被跟踪板 板心误差（中位） | 3.0 px | 4.4 px |
| **另外三块构造出来的板**（板 1）板心误差（中位） | **340 px** | **11.3 px** |
| 检测流里有几帧被记成"帧" | 1842 行（含打乱的时间轴） | 1380 帧（= 真实帧数） |

## Bug 1：检测 CSV 不是按时间排好的，而且"一行 = 一个检测"

`ULTRA_VISION_DETECTIONS_CSV` 落盘的是**一行一个检测**，而且文件里
`idx=-1`（空帧）那一支和检测那一支是**两条各自单调的流被交错写进同一个文件**
（实测 432 处时间回退，单次最大回退 ≈20 ms）。

旧版 `tools/local_fit_replay.cpp` 按**文件顺序**、**一行当一帧**喂 `tracker.track()`，
于是同时犯两个错：

1. 时间轴被打乱（`dt` 会突然变小甚至为负）；
2. 同一帧的多块板被拆成相邻的"不同帧"。

后果（静止档 |w|≤0.3、单检测，n=1420）：板心误差中位 2.68px，但 **p90=360px、
max=698px**，17% 的帧重投影误差 >20px，而且这些坏帧**全部**落在被拆散的那一支上。

修法：全量读入 → 按 `time_us` 稳定排序 → **同一 `time_us` 的检测合成一帧**。
修完之后静止档 p90 从 360px 掉到 **5.3px**，几百 px 的尾巴整个消失（1380 帧，1908 检测）。

## Bug 2（主因）：相机→云台外参被写死成 I / 0

回放器生成 Tracker 配置时，一直是硬编码：

```yaml
R_gimbal2imubody:  [1,0,0, 0,1,0, 0,0,1]
R_camera2gimbal:   [1,0,0, 0,1,0, 0,0,1]
t_camera2gimbal:   [0,0,0]
```

而实车的外参是 `configs/spv_extrinsics.yaml` 里那一组"现场标定"：

```
R_camera2gimbal ≈ [-0.0272 -0.1262  0.9916
                   -0.9865  0.0200 -0.0249       ← ≈ -90° 绕 x
                   -0.0161 -0.9918 -0.1266]
t_camera2gimbal = [0.0861, 0.1355, 0.0681] m
```

那个文件自己的注释就写着："Ultra_Vision 的 camera.yaml 那一组与 sp_vision 期望的
约定不一致（实测直接把重投影指标从 3.4px 打到 149px）"。**回放器连这组都没用。**

写死成 I 的后果：整个世界系被转错 ≈90°。追踪到的那块板**板心**还能对上
（PnP 把板放在那儿），但四块板的**形状/朝向**全错：

* 模型重投影四边形的边长比 **4.66**，同一帧检测出来的真板是 **2.44**（真值 2.45）
  → 模型把板**画扁了一倍**（56 mm 的灯条被投成 ≈29 mm）；
* 被跟踪板四角点 RMSE **87.9px**；
* 用 r 反推，模型眼里相机与板的高度角差 **≈44°**，而实际只有几度。

修法：`tools/local_fit_replay.cpp` 新增 `--extrinsics`（默认吃
`Ultra_Vision/configs/spv_extrinsics.yaml`），把 `R_gimbal2imubody` /
`R_camera2gimbal` / `t_camera2gimbal` 写进生成的配置。

修完之后同一份数据：边长比 4.66 → **2.26**，四角点 RMSE 87.9 → **11.4px**，
"另外三块板"的误差 340 → **11.3px**。

## 由此被推翻/需要重做的结论

* "sp_vision 模型在实车上只有 3.28px、系统项占 17%、随机项 sd 80px"
  —— **是喂法造出来的**（Bug 1 打乱时间轴 + Bug 2 转错世界系）。
* "NIS 门按 0.67px 定 → 全部被拒"、"放开就带偏状态"
  —— 在转错 ≈90° 的几何上做的结论，**不可用**。
* `docs/uv_ekf_feasibility.md` 里"模板/雅可比正确、单板秩亏"这些结论仍然成立
  （那是纯几何实验，不经过回放器），但**实车 A/B 数字要重跑**。

## 修正后基线（/tmp/det2.csv：1380 帧、1908 检测）

```
被跟踪板（静止档）      板心  4.4 px   四端点每分量 RMSE  7.9 px
模型里"另外几块板"      板 1  11.3 px  （修之前 340 px）
记录帧（state != lost） 1175 / 1380
```

## 本轮同时量到的其它事实

1. **同帧的两块板是同一个刚体。** 519 帧里检测到两块板；把**每一块**都做一遍 PnP
   （旧版只解被关联上的那块，其余 `xyz_in_world` 是 0）后，两者三维间距
   **中位 0.405 m（p10~p90 = 0.393~0.444）**，深度差中位 **0.04 m**。
   作为对照，用同一套统计量在**仿真**数据上（真值 r=0.2009，相邻板心间距 0.284 m）
   读出 0.31~0.32 m（偏大 ~10%）。
2. **r（装甲板半径）不是当前的限制项。** 把 4 板车的初始化半径按
   0.20 / 0.25 / 0.286 / 0.32 各跑一遍，板 1 的误差 316~356 px，几乎不动。
   所以 sp_vision 硬编码的 `0.2`（对仿真车是对的，仿真真值就是 0.2009）虽然和实车
   实测的 0.40 m 间距对不上（若两块可见板相邻 90°，r≈0.29 m），但**改 r 解决不了重投影**。
   → 想改 r 之前，请先用卷尺量一次实车"车心→装甲板面"的距离。
3. **回放器目前不可复现**：Ceres 侧用了 `max_solver_time_s` / `multi_start_budget_s`
   这类**墙钟**预算，同一份输入两次跑出来的"拟合尝试/有效"是 1371/975 与 1373/0。
   任何 A/B 要么固定这些预算，要么重复多次取中位。

## 下一步（按优先级）

1. 用**修好的**回放器重跑 UV-EKF 的 A/B（`SPV_UV_EKF=1`），
   `sigma_px` 按实测端点残差给（修好后被跟踪板是 ~8px，不是 0.67px）。
2. 把回放器的确定性修掉（固定迭代/时间预算），否则 A/B 结论不可信。
3. r 的实车真值用卷尺量一次，再决定 `SPV_TARGET_RADIUS`。

# 2026-10-15：按 JLU / RMCS 的 P0 清单改造 UV-EKF（sp_vision `uv` 分支）

参考了两个同样用"端点/重投影观测"的开源项目：
`jlu_vision_26`（重投影因子 + ISAM2）与 `rmcs_auto_aim_v2`（整车 EKF，观测就是灯条端点像素）。
逐条落地后的实测结论如下。

## 改了什么

1. **观测拆到"每根灯条 4 维" + 可见性匹配**（对齐 RMCS `RobotModel`）：
   板法向与"板心→相机"夹角 < 70° 两根灯条都可见、70°~90° 只留朝相机那根、> 90° 全不可见。
   只丢失败的那根灯条，不再整帧丢。
2. **NIS 改成窗口式**：最近 100 个灯条观测量，失败率 > 15% 就关掉 UV（对齐 JLU
   `nis_failure_window_size` / `reset_failure_percentage_thres`）。
3. **半径标定**：从代码硬编码改成配置 `tracker.radius`，默认 **0.29**（本车两种独立实测一致：
   两块同帧可见板 PnP 间距 0.405 m ÷ √2 = 0.286；放开 P0 让 EKF 自己拟合收敛到 0.287~0.29）。
   P0 里 r/l/h 的方差 1.0 → 1e-3（≈冻结，对齐 RMCS 的 rf/rl/hl 过程噪声 ≈ 0）。
   仿真车要显式给 0.2009。
4. **选板加 5° 迟滞**（对齐 JLU `armor_switch_facing_degree_diff_thres`）。
5. ω 过程噪声可配：sp_vision 原版 `v2=400` ⇒ 每帧允许 ω 变化 0.29 rad/s，等于每帧重猜一次转速；
   JLU 的 `vyaw_factor_noise=0.05` 才是"常 ω"该有的量级。

## 实测（实车 1380 帧）

最干净的指标是**静止段的状态抖动**——它不依赖观测，不会被"把模型拉到观测上"自证：

| 配置 | 帧数 | 静止A Δx / Δyaw | 静止B Δx / Δyaw | 另一块板 | ω σ (6.5~14.5s) |
|---|---|---|---|---|---|
| 旧：r0=0.2, P0=1, 无 UV | 1349 | 6.4mm / 0.18° | **41.3mm** / 3.73° | 149px | — |
| 新几何 r=0.29 冻结，无 UV | 1374 | 5.4mm / 0.18° | **14.5mm** / 3.69° | 79px | 0.94 |
| 新几何 + UV gain=0.5 | 1256 | **33.2mm / 1.33°** | **92.1mm / 6.98°** | **37px** | **2.53（且 ω 有 +1.56 的假偏置）** |
| 新几何 + UV gain=0.25 | 1370 | 3.9mm / 0.27° | 13.7mm / 3.70° | 89px | 0.98 |
| 新几何 + UV gain=0.125 | 1372 | 2.5mm / 0.21° | 13.7mm / 3.70° | 89px | 1.01 |

## 结论

* **几何修正（r=0.29 + 冻结）是净胜**：静止段位置抖动 41.3 → 14.5 mm，且跟踪帧数还多了。
  这条直接来自"半径是物理常数、不该让 EKF 自由漂"（RMCS/JLU 都是这么干的）。
* **UV 观测现在机制正确**（1500 次灯条级更新、NIS 0.1~1.8；之前恒为 0），
  但在 EKF 里**没法两全**：
  * 增益给到能改善重投影（0.5）时，静止段位置抖动 ×6、yaw 抖动 ×7、
    ω 出现 +1.56 rad/s 的假偏置、丢帧 +9%；
  * 阻尼到不伤状态（≤0.25）时，重投影与基线打平（89 vs 79px）→ 等于没效果。
* 原因是**结构性**的：模型误差是跨帧相关的系统误差，而 EKF 里没有"每帧板位姿"这种
  冗余变量可以吸收它——观测的信度调到能修正几何时，就会把底盘状态一起拖着走。
  JLU 用 ISAM2 把每帧装甲板 Pose3 当独立变量，正是为了解决这件事。

→ 因此 **UV 保持默认关**；要拿那份重投影收益，下一步是因子图（或 EKF 的"每帧位姿"增广），
而不是继续调 UV 的噪声/增益。

## 附：这一轮同时确认的其它数字

* 模型里被跟踪板的板心误差 4.0px、四端点每分量 RMSE 7.7px（外参修好之后）。
* 本车装甲板装配半径 r ≈ 0.29 m（两种独立方法一致），比 sp_vision 硬编码的 0.2 大 45%。
* ω 的过程噪声压到 v2=25 能把丢帧救回来（1256→1316），但模型会滞后、
  重投影反而变差（板心误差 p50 4.3 → 31.7px）——两个方向是耦合的。
