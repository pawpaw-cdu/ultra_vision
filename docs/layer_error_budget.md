# 分层误差预算（D8 / D9）

> 口径：`tools/auto_aim_sim_test.sh --no-build --seconds 10 --camera armor_camera_far
> --gyro 1 --gyro-speed {0.5,2,3,5}`，靶车开小陀螺、相机固定正对。每个转速跑 10s。
> 误差量全部来自脚本自带的真值对比 + `vision.log` 的每秒状态行 + 三条 CSV。
> **本轮不改算法**，只把误差量出来，并列出**执行/驱动类**的改进项。
>
> 复现命令：
> ```bash
> for sp in 0.5 2 3 5; do
>   tools/auto_aim_sim_test.sh --no-build --seconds 10 --camera armor_camera_far \
>     --gyro 1 --gyro-speed $sp --out /tmp/layer_sweep/sp$sp
> done
> ```

## 2. 误差怎么从一层传到下一层

链条：`图像 → 检测/PnP（识别层） → 关联/估计（观测层） → 选板/提前量（决策层）
→ 云台/开火（控制层）`。

| 传递 | 观测到的关系 | 传递系数（本批） | 主因 |
|---|---|---|---|
| 识别 → 观测 | observation 0.12~0.16 m，关联接受率 ~40% | 起决定作用 | 远处靶像素少、几何退化 |
| 观测 → 决策 | accepted 少时 `plate_switches` 高（sp=2/3 约 60/9s） | 强相关 | 断续观测 → 板号在相邻板间跳 |
| 识别 → 中心 | center / observation ≈ **1.5~2.1×** | 放大 ~2× | 单板 PnP 误差传到整车几何 |
| 观测 → 控制 | `ω` 相对误差 ≤2%（≥2 rad/s）时 fire window ≥74% | 弱相关 | 估计稳时控制稳 |
| 决策 → 控制 | `in_fire_window` 与 `aim_settled` 同向（sp=5：100% vs 95%） | 强相关 | 决策稳 → 控制余量大 |
| 控制 → 命中 | yaw_err < 1.5°、pitch_err < 0.7° | — | 落点误差主要不在这层 |

**结论（用于排序改哪里）**：本批工况下**识别层是主导项**（observation 0.12~0.16 m），
中心误差是它的 ~2 倍放大；观测层在 ≥2 rad/s 已经很稳（ω 误差 ≤2%），瓶颈是
**慢转信噪比**（0.5 rad/s 时 ω 误差 52.6%）与**关联丢弃率 ~40%**。控制层误差
（<1.5°）相对识别层小一个量级。

## 3. 可优化项（**只列执行/驱动类，不调算法参数**）

按"能减少识别/观测层误差或降低延迟"排序：

1. **曝光时刻时间基（C7）**：真机现在用处理时刻当帧时间戳，姿态按 `≈now` 插值，
   等于丢掉了"曝光→到手"那几十毫秒。补上相机驱动的时间戳，观测年龄与姿态对齐后才能
   把现有估计精度**兑现**出来。仿真已对齐；真机见 `docs/io_driver_and_timebase.md`。
2. **动态 ROI 的执行开销**：ROI 本身不降检出率，但投影/裁剪在 `work` 段里；把它挪到
   检测线程（已有异步检测器线程）可减少主循环 work，见 `vision.log` 的 stage ms。
3. **丢帧/队列深度**：`net: decode_dropped` 与相机"只留最新几帧"，确认没有把"最新的
   曝光帧"丢掉；丢帧直接体现为观测年龄变大。
4. **关联丢弃率 40%**：`nomatch/ambiguous/scale` 三个数是执行层可观测的入口；先量化
   是"检测框不够"还是"关联闸门过严"（只加**计数器/日志**，不改判据）。
5. **下发频率 100→200/500Hz（C6）**：需先与电控确认协议字段与固件内插行为，见
   `docs/io_driver_and_timebase.md` §C6；未确认前不动。
6. **相机采集分辨率/曝光**：`configs/camera.yaml` 的 `simulator.max_processing_width`
   与实车标定尺寸一致，仿真帧偏小会按面积缩水检出率（`node_sim` 已打印警告）。

> 以上都不动滤波器/控制器参数；它们的作用是**把已有精度的上限兑现**，用量表衡量。
