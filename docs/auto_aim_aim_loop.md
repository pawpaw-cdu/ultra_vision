# auto_aim 瞄准闭环：口径、实测、当前结论

2026-09-26。配套工具 `tools/auto_aim_aim_check.py`，配套工况开关
`tools/auto_aim_sim_test.sh --distance/--pan/--pan-lead/--gyro`。

## 1. 仿真里的瞄准闭环长什么样

`simulator/src/main.rs::remote_camera_gimbal` 会把**我们下发的云台指令**直接
变成**主相机的位姿**：

```
camera_rotation = home_rotation · R_y(-cmd_yaw) · R_x(cmd_pitch)
```

所以 `truth.csv`（板子在**当前相机系**里的位置）本身就是一个闭环量。实测符号
关系（给仿真发一条指令，等 0.4 s 再看真值）：

| 下发指令 | 靶面 apparent yaw | 靶面 apparent pitch |
|---|---|---|
| `GIMBAL 0 0` | -0.02° | +0.28° |
| `GIMBAL +5° 0` | **-5.02°** | +0.28° |
| `GIMBAL 0 +5°` | -0.02° | **-4.72°** |

即 `apparent = 基线 - cmd`。这和视觉端的模型是自洽的：视觉端算的是
"当前指令角 + 相机系里的目标角"= 绝对指令角，所以闭环一步收敛而不是正反馈
（这一点必须实测确认过，符号反了会变成云台一路跑飞）。

## 2. 对账时必须把真值转回 home 系

selector.csv 的 `target_yaw/target_pitch` 是 **home 系（云台零位系）角度**，
而 truth.csv 是**相机系**位置。所以：

```
yaw_home   = atan2(x, z)      + cmd_yaw
pitch_home = atan2(-y, hypot(x,z)) + cmd_pitch
```

`cmd_yaw/cmd_pitch` 取同一时刻的 `observation.csv`（它就是视觉端用来反旋观测的
那一组角）。**别直接用相机系角度比 target_yaw**，差一个 cmd 量级。

还有一项是"故意"的偏差：selector 瞄的是**抬了 0.5·g·t_fly² 的瞄准点**，
6.5 m / 25 m/s 时 ≈ 3.1~3.5°（0.47 m）。工具默认扣掉（`--no-ballistic` 可看原始值）。

## 3. 指标定义

* `pred`：selector 在 t 时刻给出的 (t+lead) 预测角 vs **真值在 t+lead 时刻**
  最近板的 home 系角；取最近板是因为四板相隔 90°，1~2° 误差不可能认错。
* `横向误差`：`Δyaw × 距离`（cm）。距离用真值，不用估计。
* `提前量欠量`：把误差投影到**真值该板的 home 系角速度**方向：
  `-(Δyaw·ω_yaw + Δpitch·ω_pitch)/|ω|²`。正数 = 瞄点在靶后面。
  注意必须用 **home 系**角速度：相机系角速度里混着"云台自己转"的成分
  （实测能到 20~50 deg/s，比靶的运动大一个量级）。
* `指向偏置(⊥)`：扣掉提前量分量后剩下的部分，是真正的静态指向误差
  （滤波器再怎么调也改不了，得查 PnP/标定/中心定义）。

## 4. 本轮实测（6.5 m，1440x1080，仿真）

工况：`--pan 0.8` = ±2 m 来回 @0.8 m/s，段与段之间速度是**阶跃**的
（等价于实车按 WASD/R 键那种"瞬时给速度"，也正是"跟不上平移"最刺眼的地方）。

| process_noise_pos | 横向误差 中位 | p10 / p90 | 平移段欠量 中位 | 近距 1 m FIRING |
|---|---|---|---|---|
| 1（原值） | +0.3 cm | −18.9 / +24.3 | +48 ms | 81 / 115 / 82 |
| 10（常数） | +0.1 cm | −9.6 / +10.0 | +17 ms | **16 / 15 / 17** ← 回归 |
| 30（常数） | +0.9 cm | −9.0 / +9.1 | +24 ms | 未测 |
| 100（常数） | — | 决策占空 85%→36% | — | — |
| **自适应（现值）** | −0.1 / +0.3 cm | −13.8 / +11.2 | +59 / +80 ms | 104 / 113 |

结论：**常数调大能治平移，但会把近距静态工况打死**——过程噪声的物理含义是
"底盘加速度的不确定度"，静止时本来就该是 0。所以改成按速度自适应：

```
qa = clamp(process_noise_pos · (1 + (|v|/speed_ref)²), ·, process_noise_pos_max)
speed_ref = 0.28 m/s, max = 40       # |v|=0.8 m/s → qa≈9.2，≈实测最优的常数 10
```

旋转靶（`--gyro 1`，2.4 rad/s）对这三个值都不敏感：横向 p10/p90 都在 −8/+7 cm，
欠量 −26→−2 ms，FIRING 94/110/102 → 自适应 93，**没有回归**。

## 5. 仿真环境本身的两个坑（会污染测量）

1. **`DAEDALUS_MOVE_LOOP` 原来完全不生效**，三处 bug：
   `scheduled_vehicle_input` 挂在 `remote_vehicle_controls` 里，而那个系统要
   `Single<(&mut Transform, &mut InfantryChassis), ...>`，`armor_chassis` 场景的
   靶车（`spawn_vehicle_scene`）**没有** `InfantryChassis` 子节点 → `Single` 匹配
   0 个实体 → 整个系统被 Bevy 跳过（日志里一行 `[move]` 都没有）；
   段时长被当成绝对时刻用；段表还被按第一列排了序。已修，并改成独立的
   `scripted_vehicle_motion`（只依赖 `InfantryRoot`），用 `MainCameraHome`
   作参考系（用当前相机位姿的话，运动方向会跟着云台转，靶车绕着相机画圈）。
2. **靶车在仿真里会被"推着走"**：不加任何脚本运动时，6.5 m/1 m 工况下中心
   仍会自己漂 0.3~1.9 m（子弹命中冲量 + 自身沉降/与本地机器人碰撞都可能是来源）。
   所以"静止工况"并不静止，比 q 值更小的影响都会被它淹掉。下一步应该把
   `armor_chassis` 场景的靶车锁成完全不动（或让弹丸不与靶车碰撞）。

## 6. 还没解决：锁定（acquire）很脆

现象（`--pan 0.8 --gyro 1`）：首帧同时看到 4 块板时，跟踪器**永远锁不上**
（`observation.csv` 0 行、`lost` 一路涨），而 selector 里那条冻结的估计
（真值 6.5 m，估计出来的"板"在 1~2 m）会把云台一路带到 80~90° 出画，
整轮再也回不来。同一工况重跑 3 次都是"首帧 armors=2 → 正常锁定（344/346/343 行观测）"。
最早那轮 3 s 前导静止的 pan 工况也是这个死法（14 条决策、云台转到 86°）。

这和用户报的"识别不到"是同一件事：**不是距离问题，是锁定期的脆弱 + 云台会追着
假目标跑**。下一步优先级：

1. 云台指令加"确认"闸门：`TEMP_LOST`/刚重捕/估计跳变超过阈值时**保持**而不是跟；
2. 首帧多板时先做几何一致性（四板半径 0.21 m、角度互差 90°），别让单块假板定生死；
3. 给估计的距离加"和靶面像素尺度一致"的硬闸门（1~2 m 的假解在这个闸门下会直接被拒）。
