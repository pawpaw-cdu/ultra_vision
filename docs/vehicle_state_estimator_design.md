# 整车状态估计器设计经验

> 适用范围：RoboMaster 装甲板自瞄中的底盘运动状态估计。
>
> 本文总结当前 `Ultra_Vision` 的 `Tracker + ArmorEKF` 实现，并结合 `sp_vision_25` 一类整车估计方案，整理设计原则、调试经验和后续演进方向。

## 1. 先明确系统的工程定位

这套模块最准确的称呼是“估计器”，核心算法是“扩展卡尔曼滤波器”：

- `ArmorEKF`：对带噪声的装甲板观测进行递归状态估计，属于非线性卡尔曼滤波器。
- `Tracker`：负责初始化、装甲板关联、状态机、多板几何拟合，属于整车状态估计器。
- 整个模块可以称为“基于 EKF 的递归整车状态估计器”。

它不属于严格意义上的确定性状态观测器。过程模型和观测模型都带有随机噪声，输出不仅是状态值，还包括状态协方差和观测门限判断。

## 2. 为什么要估计整车，而不是只跟踪可见装甲板

仅对当前可见装甲板做滤波，通常会遇到以下问题：

1. 只能获得当前装甲板的位置和朝向，无法表达底盘整体姿态。
2. 装甲板切换时，直接跟踪会导致 yaw、位置和速度产生跳变。
3. 短暂遮挡后，滤波器不知道其他装甲板应该出现在哪里。
4. 左侧和右侧装甲板分别更新时，可能重复把同一个底盘中心的误差注入状态。
5. 静止时，PnP 抖动会被误解释成底盘速度和角速度，产生持续漂移。

整车估计的基本思路是：

> 把底盘中心、线速度、yaw 和角速度作为待估计状态，把每块装甲板看成底盘几何模型上的一个观测点。

这也是 `sp_vision_25` 一类实现的核心思想：跟踪的是“车”，不是单独跟踪这一帧恰好可见的那块板。

## 3. 推荐的数据流

```text
相机图像
  -> 灯条检测与装甲板配对
  -> 装甲板 PnP
  -> 装甲板三维位置、姿态和径向角
  -> 装甲板与底盘模型的几何关联
  -> EKF 预测与观测更新
  -> 底盘中心、速度、yaw、角速度、四块装甲板位置
  -> 可视化、目标选择、预测和火控
```

各层职责应保持清晰：

| 模块 | 输入 | 输出 | 主要职责 |
|---|---|---|---|
| Detector | 图像 | 灯条、装甲板 | 图像检测和几何筛选 |
| PnP | 装甲板角点 | `rvec`、`tvec` | 相机坐标系定位 |
| Tracker | PnP 观测集合 | 整车状态和板号关联 | 初始化、关联、状态机 |
| ArmorEKF | 单板或多板观测 | 状态、协方差 | 预测和递归更新 |
| Controller | 估计状态 | 云台和目标指令 | 弹道、控制和火控 |

不要让 Detector 或 PnP 直接承担状态估计。它们只负责产生带有不确定性的观测。

## 4. 坐标系和状态定义

### 4.1 坐标系必须显式定义

当前实现主要工作在相机坐标系下。近似认为相机光轴水平、相机无明显 roll 时：

- `x`：水平横向。
- `y`：竖直方向。
- `z`：水平前向。
- `x-z`：底盘附近的地平面。

因此当前模型的底盘中心记为：

```text
c = [x_c, y_c, z_c]
```

工程中一定要在代码和文档里明确：

- 状态是在相机坐标系、云台坐标系还是世界坐标系。
- PnP 输出是否经过了手眼变换。
- 相机姿态是否已经补偿。
- `y` 轴的正方向是向上还是向下。

坐标系不明会导致“滤波公式正确，但状态含义错误”的典型问题。

### 4.2 当前 EKF 状态

当前状态为 9 维：

```text
x = [x_c, vx, y_c, vy, sin(theta), cos(theta), omega, z_c, vz]
```

其中：

- `x_c, y_c, z_c`：底盘中心位置。
- `vx, vy, vz`：底盘中心速度。
- `theta`：底盘 yaw。
- `omega`：底盘 yaw 角速度。

使用 `[sin(theta), cos(theta)]` 表示角度，而不是直接使用 `theta`，原因是：

- 避免角度跨越 `-pi/pi` 时发生数值跳变。
- 线性预测时更容易保持单位圆约束。
- 每次预测和更新后只需要重新归一化 `sin/cos`。

代价是可读性略差，并且需要额外的角度归一化逻辑。

### 4.3 装甲板几何模型

四块装甲板按固定半径分布在底盘水平圆上。设第 `i` 块板的圆周角为：

```text
phi_i = theta + angleForPlate(i)
```

则装甲板中心的位置为：

```text
p_i = [
    x_c + R * cos(phi_i),
    y_c,
    z_c + R * sin(phi_i)
]
```

从这个位置可以直接得到第 `i` 块装甲板的径向角：

```text
alpha_i = atan2(p_i.z - z_c, p_i.x - x_c) = phi_i
```

PnP 得到的装甲板法向和径向角之间存在几何关系。可见装甲板正面朝向相机，因此需要根据法向与位置向量的点积修正方向。

## 5. 动态模型设计

### 5.1 当前采用的基本模型

当前模型可以概括为：

- 底盘中心在 `x-z` 平面上做近似匀速运动。
- 竖直方向 `y` 也使用近似匀速模型。
- yaw 按恒定角速度 `omega` 演化。
- 不考虑 roll、pitch、底盘倾斜和结构形变。

预测公式可以写成：

```text
x_c'  = x_c + vx * dt
y_c'  = y_c + vy * dt
z_c'  = z_c + vz * dt
theta' = theta + omega * dt
```

状态转移矩阵的非零项主要来自：

```text
dx/dvx = dt
dy/dvy = dt
dz/dvz = dt
dtheta/domega = dt
```

### 5.2 过程噪声 `Q` 的意义

`Q` 描述模型没有建模的加速度和角加速度：

- `Q` 太小：滤波器过度相信匀速模型，转向和加速时产生滞后。
- `Q` 太大：滤波器更容易相信单帧测量，静止时抖动和漂移会加重。
- `Q` 的位置、速度块需要保持连续时间白噪声模型，不能只在对角线上随意填数。

静止漂移通常不是把 `Q` 调大就能解决的问题。很多情况下，漂移来自错误关联或多板重复更新，而不是模型加速度不足。

### 5.3 时间步长 `dt`

`dt` 必须来自真实时间戳，而不是固定假设。

建议：

- 使用单调时钟。
- 设置合理的超时阈值，例如 `dt > 0.1 s` 时直接复位或进入丢失状态。
- 对异常小 `dt` 做下限保护，避免协方差计算数值不稳定。
- 不要在视频回放时使用处理速度代替视频时间。

`sp_vision_25` 的 Tracker 会在 `dt > 0.1 s` 时判定相机可能离线并重置状态，这是一个很实用的工程保护。

## 6. 观测模型设计

### 6.1 一块装甲板提供什么观测

一块装甲板经过 PnP 后可以提供：

- 相机坐标系下的三维位置 `p_i`。
- 装甲板姿态 `rvec`。
- 装甲板法向。
- 间接得到的径向角 `alpha_i`。

需要注意，PnP 的深度和姿态误差通常具有方向相关性。当前主路径将 PnP 结果转换为 `[bearing yaw, pitch, distance, armor yaw]`，分别设置测量方差；`y_noise_mult` 只保留给缺少径向角时的 Cartesian 回退路径。

### 6.2 单板观测的可观测性

单板条件下不能把所有状态都当作强可观测：

- 通过已知半径和径向角，可以由板位置反推底盘中心。
- 在假定当前板号的情况下，可以从径向角恢复 yaw。
- 角速度 `omega` 通常不能仅凭单帧位置稳定观测。
- 当板号不确定时，yaw 可能存在多解或半圈歧义。

因此单板初始化必须使用明确的板号约定和几何假设，并在状态机中尽量快速积累连续观测。

当前实现将单板锚定到约定板号，再由 PnP 径向角计算 yaw。这是比“默认 yaw 等于 0”更合理的做法，但仍然依赖板号假设。

### 6.3 当前采用 YPD 观测

当前 EKF 状态仍然是 Cartesian，测量则由 PnP 转换到 YPD：

```text
z = [yaw, pitch, distance, armor_yaw]
```

其中：

```text
yaw      = atan2(p_x, p_z)
pitch    = atan2(p_y, sqrt(p_x^2 + p_z^2))
distance = sqrt(p_x^2 + p_y^2 + p_z^2)
armor_yaw = theta + phi_i
```

对应 EKF 观测函数为 `h(x, plate_id)`。`yaw`、`pitch` 和 `armor_yaw` 的残差都经过 `[-pi, pi]` 归一化，避免 yaw 跨越正负 pi 时产生错误残差。

这样做的原因是：

1. 像素和边缘误差在角向方向上更接近高斯分布。
2. bearing 与 range 分开建模，可以减少 PnP 深度噪声对横向和姿态状态的污染。
3. 可以对 yaw、pitch、range、armor yaw 分别设置噪声。
4. 目标自转时，range 和 pitch 相对稳定，而 yaw 可以单独跟踪。

当前 range 方差还会按距离膨胀：

```text
R_distance = base_range_noise * (1 + distance_scale * distance^2)
```

状态运动模型仍保持 Cartesian，因为底盘平移预测和四板圆周几何在该空间更直接。YPD 只改变测量空间，不把整个预测器改成极坐标。

### 6.4 多板观测的价值

当两个或更多装甲板同时可见时：

- 底盘中心可以由多个板共同约束。
- yaw 可以从板间方向更稳定地恢复。
- 左右板的 PnP 误差可以通过统一模型平均。
- 角速度可以通过连续帧的 yaw 变化估计。

多板并不一定意味着直接增加观测次数。相同底盘中心在短时间内的多个板观测是相关的，不能简单地把每个板都当成独立观测重复更新中心。

## 7. 初始化设计

初始化是整车估计器最容易出错的部分。

### 7.1 不要用检测顺序决定板号

错误做法：

```text
第一块检测到的装甲板 = plate 0
第二块检测到的装甲板 = plate 1
```

检测顺序会随画面、轮廓排序和目标运动变化，直接使用会导致 yaw 跳变。

正确做法是让板号由几何关系和模型决定：

1. 先由 PnP 径向角反推底盘中心候选。
2. 枚举板号排列，通常最多 `4! = 24` 种。
3. 对每种排列拟合 yaw。
4. 计算装甲板位置、角度残差。
5. 选择总分最低且满足残差门限的排列。

### 7.2 单板初始化

单板初始化可以按以下步骤：

1. 从 PnP 取得装甲板位置和可见面法向。
2. 修正法向方向，得到径向角。
3. 使用固定半径反推底盘中心。
4. 由径向角和约定板号恢复 yaw。
5. 初始化速度为零，角速度为零。
6. 给位置和角度较小的初始协方差，给速度较大的初始协方差。

速度不要一开始就给得很自信。初始速度应该允许后续几帧估计出来，而不是在第一帧就假定目标正在运动。

### 7.3 多板初始化

多板初始化应同时估计：

- 底盘中心。
- yaw。
- 每块观测对应的板号。

当前实现使用枚举排列和候选 yaw 搜索，避免了“先猜板号再拟合中心”造成的局部最优。

初始化后不应立即进入完全跟踪状态，通常保留若干帧确认：

```text
LOST -> DETECTING -> TRACKING
```

这样可以把偶发误检挡在稳定状态之外。

## 8. 数据关联设计

### 8.1 关联不只是最近邻

装甲板关联应至少同时考虑：

- 位置距离。
- 径向角误差。
- 当前 yaw 和角速度预测。
- 上一帧板号。
- 观测残差与协方差是否一致。

当前实现的关联代价近似为：

```text
cost = position_distance + angle_weight * angle_error
```

同时使用两个门限：

- 位置距离门限。
- 最大角度误差，当前约为 40 度。

这比只使用三维距离更可靠，因为不同板在空间中可能非常接近，但径向角差异明显。

### 8.2 关联需要迟滞

如果每帧都选择代价最小的板号，目标静止时也可能在相邻板之间来回切换。

应使用迟滞策略：

- 保持当前板号，除非新板号的代价明显更低。
- 连续多帧确认后才允许切换。
- 记录最近观测板号，并对异常切换做诊断。

迟滞不是降低响应速度，而是避免把检测噪声解释成底盘跳变。

### 8.3 NIS 门限

更新前应计算新息和马氏距离，简称 NIS：

```text
nis = residual^T * S^-1 * residual
```

如果 NIS 超过阈值，应拒绝该观测，而不是无条件更新。

当前使用的门限：

- 三维位置：`7.815`，对应 3 自由度 95% 卡方门限。
- 单角度：`3.841`，对应 1 自由度 95% 卡方门限。

门限的意义是保留模型和观测一致的更新，拒绝明显异常点。

## 9. 更新顺序和防止重复注入

多板更新最容易犯的错误是：

```text
对第一块板更新一次底盘中心
对第二块板再更新一次同一个底盘中心
对第三块板再更新一次同一个底盘中心
```

如果这些板来自同一帧和同一底盘，它们的底盘中心误差是高度相关的。重复更新会产生以下后果：

1. 协方差被错误缩小。
2. 滤波器过度自信。
3. 单板 PnP 的偏差被多倍放大。
4. 多板静止时底盘中心漂移更明显。

更合理的顺序是：

1. 先由多板几何拟合完成板号关联。
2. 将同一帧的所有有效板观测组成一个联合 YPD 测量向量。
3. 只执行一次批量 EKF 更新。
4. 用每块板单次 NIS 门限过滤异常观测，再使用所有通过门限的板联合更新共享状态。

当前实现已经使用 `updateYpdBatch()` 完成这一过程。它不会对同一底盘中心连续做多次独立更新，因此避免了协方差被重复缩小和目标静止时的中心漂移。

## 10. 静止漂移的根因与治理

静止漂移通常不是一个参数造成的，常见根因如下：

| 根因 | 表现 | 处理原则 |
|---|---|---|
| 板号关联跳变 | yaw 和中心突然改变 | 角度残差门限、迟滞、连续确认 |
| 多板重复更新中心 | 姿态越更新越自信，中心缓慢漂移 | 先拟合聚合中心，再更新角度 |
| PnP 深度抖动 | 前后方向漂移 | 使用位置 NIS、增大对应测量噪声 |
| PnP 竖直方向噪声 | `y` 上下跳动 | 提高 `y` 噪声，使用独立噪声权重 |
| 错误初始化 | 开始阶段就存在固定偏移 | 单板几何反推、多板枚举初始化 |
| `Q` 过大 | 静止时随机游走明显 | 降低过程噪声，尤其角速度噪声 |
| 缺少速度阻尼 | 零观测时速度和角速度持续外推 | 丢失状态衰减速度和角速度 |
| `dt` 异常 | 预测距离错误，状态突然跳变 | 单调时钟、超时复位、dt 限幅 |
| 相机自身运动 | 相对目标速度被误认为目标运动 | 接入 IMU、云台和坐标系变换 |

特别要注意：

> 静止时“中心均值看起来正确”不代表估计器稳定。应该看中心、yaw、速度和角速度的标准差、峰峰值和折返次数。

## 11. 状态机和丢失处理

推荐保留明确的状态机：

```text
LOST -> DETECTING -> TRACKING -> TEMP_LOST -> LOST
```

各状态的职责：

- `LOST`：没有可靠目标，等待初始化。
- `DETECTING`：已有候选目标，但尚未达到稳定确认帧数。
- `TRACKING`：状态收敛，可以输出用于预测和控制。
- `TEMP_LOST`：短时间内没有满足关联的观测，继续用模型外推。

丢失处理原则：

1. 短暂丢失时继续预测状态。
2. 速度和角速度逐步衰减，避免长时间保持错误运动趋势。
3. 超过最大丢失帧数后进入 `LOST`。
4. 再次观测到时，需要重新确认而不是直接恢复高置信度。

状态机应和滤波器分离。EKF 负责数值状态，Tracker 负责“是否有资格继续相信这个状态”。

## 12. 参数调试顺序

建议按以下顺序调试，不要同时修改所有参数：

1. 相机内参、畸变和相机 FOV。
2. PnP 使用的装甲板真实尺寸。
3. 底盘装甲板分布半径 `R`。
4. 位置观测噪声和角度观测噪声。
5. 位置 NIS 和角度 NIS 门限。
6. 过程噪声 `Q`。
7. 关联距离、角度门限和切换迟滞。
8. 状态机确认帧数和最大丢失帧数。

调试原则：

- 先保证 PnP 和 `R` 正确，再调滤波器。
- 先让静止稳定，再调动态响应。
- 先用回放数据做确定性测试，再做实时测试。
- 每次只改一组参数，并保存日志。

## 13. 测试和评价指标

### 13.1 建议的测试场景

至少覆盖：

1. 单板静止。
2. 单板平移。
3. 单板连续旋转。
4. 双板可见且静止。
5. 双板切换和遮挡。
6. 多板同时可见。
7. PnP 噪声和异常值注入。
8. `dt` 抖动和丢帧。
9. 相机自身移动或旋转。

### 13.2 评价指标

对中心、yaw、速度和角速度分别统计：

- RMSE。
- 最大误差。
- 静止时的方差和峰峰值。
- 收敛时间。
- 超调量。
- 板号切换次数。
- 被 NIS 拒绝的观测比例。
- 状态机切换次数。
- 重投影误差和残差分布。

只看平均误差不够。自瞄控制更关心：

- 静止时是否漂移。
- 换板时是否跳变。
- 遮挡后是否快速恢复。
- 预测是否连续。

## 14. 与 `sp_vision_25` 类整车估计器的对照

`sp_vision_25` 的 `Target` 使用了更完整的整车状态：

```text
[x, vx, y, vy, z, vz, angle, omega, r, l, h]
```

相比当前 `Ultra_Vision` 的 9 维状态，它额外考虑了：

- 装甲板圆半径 `r`。
- 不同装甲板半径差 `l`。
- 高度差 `h`。

这类模型可以支持不同车型和不同装甲板几何结构，例如普通机器人、前哨站和基地。其核心经验包括：

1. 状态模型应该跟随车体和装甲板类型变化，而不是所有目标都固定为同一种几何。
2. 观测应尽量使用稳定的角度、俯仰和距离组合，而不是只使用原始三维点。
3. 测量噪声应根据距离、角度和观测条件变化。
4. 除数值滤波外，还需要发散检测、收敛检测、跳板检测和状态机。
5. Tracker 负责目标选择和状态管理，Target/EKF 负责车辆状态。

当前项目不需要立即照搬全部 11 维状态，但应把“固定半径和固定板数”视为当前模型假设，而不是通用事实。

## 15. 当前项目中的模块映射

当前 `Ultra_Vision` 的核心实现如下：

| 文件 | 作用 |
|---|---|
| `src/auto_aim/Kalman/armor_ekf.hpp` | 9 维 EKF、状态预测、位置和角度更新、协方差传播 |
| `src/auto_aim/Kalman/tracker.cpp` | 初始化、单板/多板关联、状态机、整车模型拟合 |
| `src/auto_aim/perception/detector.cpp` | 灯条和装甲板检测 |
| `src/auto_aim/perception/pnp_solver.cpp` | 装甲板 PnP 定位 |
| `src/auto_aim/node_sim.cpp` | TCP 仿真图像、统一整车估计、可视化和 FIRE |
| `src/auto_aim/node.cpp` | 实车相机入口，与仿真共用同一个整车 Tracker |
| `src/auto_aim/config_loader.hpp` | 两个入口共用的 detector/tracker/PnP 配置解析 |
| `src/auto_aim/visualization/projection.hpp` | 两个入口共用的整车模型投影叠加 |
| `configs/tracker.yaml` | EKF、关联、NIS 和状态机参数 |

当前两条入口已经统一到同一个整车估计器：

> 仿真入口和实车入口都使用单个整车 Tracker、同一套 `config_loader.hpp`
> 配置解析和同一套 `projection.hpp` 可视化，多板观测通过 `updateYpdBatch()`
> 一次批量更新。

仍然存在的差异是坐标系和闭环范围：仿真入口通过 `CameraPose` 把估计提升到
世界系并接入了选择、云台和火控，实车入口目前没有云台角度与 IMU 反馈，因此
以恒等 `CameraPose`（即相机系）运行，只做估计和可视化。接入姿态反馈后，只需
在 `update()` 前调用 `tracker.setCameraPose()`，估计器无需再改动。

## 16. 当前方案的边界

当前实现还没有解决以下问题：

1. 实车入口的底盘中心仍是相机坐标系下的相对估计；仿真入口已通过 `CameraPose` 升到世界系，实车缺少姿态反馈。
2. 没有接入 IMU、云台角度和手眼变换。
3. 没有显式补偿相机自身运动带来的相对速度。
4. 装甲板半径固定为 `0.21 m`，没有估计半径误差和车型差异。
5. 没有真实装甲板数字分类，`plate_id` 只是几何编号。
6. 没有完整云台控制、弹道补偿和射击闭环。
7. 实车入口已迁移到统一整车 Tracker，但仍未接入选择、云台和火控闭环。

这些限制意味着目前的状态估计更适合作为视觉预测核心，而不是完整的火控状态源。

## 17. 设计检查清单

每次修改整车估计器前检查：

- [ ] 坐标系是否明确，单位是否为米和弧度。
- [ ] 相机内参、畸变和装甲板尺寸是否真实可靠。
- [ ] 底盘半径 `R` 是否经过实测。
- [ ] 单板初始化是否依赖检测顺序。
- [ ] 多板关联是否同时使用位置和角度。
- [ ] 板号切换是否有迟滞。
- [ ] 多板是否重复更新了同一个底盘中心。
- [ ] 是否为 `y` 方向和角速度设置了合理的观测噪声。
- [ ] 是否有位置和角度 NIS 门限。
- [ ] 丢失状态是否衰减速度。
- [ ] `dt` 是否有异常保护。
- [ ] 是否测试了静止漂移、换板跳变和短暂遮挡。
- [ ] 是否记录了状态协方差、NIS 和板号切换日志。
- [ ] 实车和仿真是否使用同一套 Tracker 架构。

## 18. 结论

整车状态估计器的关键不在于“把 EKF 公式写出来”，而在于建立正确的几何关系和观测语义：

1. 先用几何模型把可见装甲板转换成底盘中心与 yaw 的观测。
2. 再将单板、多板和丢失状态统一到一个车辆状态模型中。
3. 通过合理的关联、门限和更新顺序防止错误观测污染状态。
4. 最后才通过参数调节改善动态响应和静止稳定性。

对当前项目而言，最有价值的设计经验是：

> 单板时用 PnP 径向角恢复底盘中心；多板时先拟合共享中心，再更新各板角度；任何板号切换、中心更新和角度更新都必须经过几何一致性与统计门限检查。

后续最优先的工程改动不是继续堆滤波参数，而是：

1. 在实车入口接入云台角度与 IMU 反馈，把估计从相机系切换到云台/世界坐标系。
2. 把实车入口接入选择、云台和火控闭环，替换当前仅估计加可视化的形态。
3. 将固定半径模型扩展为可配置或可估计的车型模型。
4. 建立地面真值回放和静止漂移自动评测。
