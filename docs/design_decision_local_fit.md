# 决策：局部拟合器"收缩"定位 + 6D 建模暂停（2026-10-12）

> 背景：拟合器本体已验证（干净仿真弧 1.54px、ω 误差 10%），但接入主链路后**没有产生
> 可测量的收益，还会在已经稳定的工况上引入不确定度**；"修一处冒一处"反复出现。
> 经与用户讨论，决定：**按 A 方案收缩**，把"6D 完整位姿"当研究项而非目标。
>
> 本文是**决策记录 + 验收门槛**，不是待办清单。所有数字都来自
> `docs/plan_audit_6d_pose.md` 里可复现的实验。

---

## 1. 为什么收缩：三个失败模式，各有各的负责人

同一份实车检测流（det2.csv，1380 帧），四角点重投影口径（"取最贴"= 不依赖板号，
"配对"= 同板号）：

| 工况 | 现状 | 病灶归属 |
|---|---|---|
| **正对 + 静止** | **5.0 px**（板心 2.65px） | **没有病**。PnP+EKF 在这里是优秀的 |
| **正对 + 自旋** | ≈49 px（≈30px 是板形/朝向 ⇔ 20–30° yaw 滞后；42.7px 是中心位置 ≈2.4cm） | **动态层**：CV 模型 + 平滑滤波有 ∝ω 的滞后 |
| **斜视（不分工况）** | 模型就在观测附近（**52 px**），但 **≈19% 帧板号认错**（配对 715px） | **识别/关联层**：板号依赖病态的 PnP yaw |

拟合器自己的分层成绩（拟合 rmse）：

| 档位 | n | 中位 | ≤3px |
|---|---|---|---|
| \|ω\|≤2（近似静止） | 147 | 3.70 px | 38.1% |
| **\|ω\|>2（自旋）** | 196 | **17.83 px** | **0.0%** |

→ **它在没有改善空间的档位好用，在唯一有价值的档位出不了可用解。**

---

## 2. 决策：拟合器 = 动态层的 ω 观测源（只此一项）

### 2.1 定位（写死）

1. **只做 ω 观测源**。yaw 通道关闭（`use_yaw: false`）——它目前只会加不确定度。
2. **不参与位置、深度、几何**：
   * 位置：PnP 强项（正对·静止 5px）；
   * 深度：PnP 的 t_z 实测 **5.8mm**，比拟合器的 10–50mm 准 2–9 倍；
   * 几何（R/α/h）：`use_fit_radius: false`（实测打开后"正对·静止"退 41px）。
3. **只在自旋档注入，且必须有质量证据**：`omega_max_rmse_px=3.0`
   （拟合没贴住观测时连 ω 一起丢；实测放开它会从 32.6px 劣化到 69.7px）。

### 2.2 为什么"6D 完整建模"不是目标

方案的主线是 *6D 病态 → 4D → 拟合器给 ψ,Z → 2D → 完整 6D 位姿*。但数据显示：

* 正对时**位姿本来就没病**（5px）；
* 病态的只有**朝向（yaw）**，而它只被两处需要：**板号/相位** 与 **EKF 的 armor_yaw 观测**；
* 位置与深度**不需要拟合器**（PnP 更强）。

"完整 6D 位姿"是**手段不是目的**；为一个不需要的中间量付了很高的耦合成本，
而它要解决的两个真问题（动态滞后、身份）都没解决。
**一个模型同时承担 位置/朝向/身份/动态预测 四件事**，正是"修一处冒一处"的结构来源。

## 3. 护栏（防止再长回去）

| 配置 | 值 | 实测依据 |
|---|---|---|
| `local_fit.enabled` | **false** | 默认关；只在自旋档做实验时打开 |
| `local_fit.use_yaw` | **false** | 正对·静止 6.24 → 8.22px（变差 32%）；自旋档无改善 |
| `local_fit.use_fit_radius` | **false** | 打开后正对·静止退 41px（74.0 vs 32.6） |
| `local_fit.also_update_center` | false | 中心由位置观测决定，不需要拟合器 |
| `local_fit.center_anchor` | false | 实测把它打开的版本模型更差 |
| `local_fit.omega_max_rmse_px` | 3.0 | 放开后 32.6 → 69.7px |

**验收门槛（任何改动都要过）**：

1. **"正对·静止"不许退化**（当前 5.0px）—— 这是整个系统唯一干净的地基；
2. 自旋档"≤3px 占比 ≥30%"才允许注入；
3. 自旋档四角点中位 55 → **≤20px** 才算有收益。

## 4. A 方案的工作面（资源投这里）

| 优先级 | 工作面 | 为什么 |
|---|---|---|
| 1 | **身份/关联**：板号改成**相位连续性（增量）**，不再逐帧从 EKF 状态反推 | 斜视 19% 帧认错板是当前最大的单点误差（715px） |
| 2 | **时间基 + 关键点定义**：曝光时间戳、IMU 插值、NN 关键点与"灯条/板角"的定义对齐 | 它是识别层 0.12–0.16m 的物理来源；也是 B 的答案候选 |
| 3 | **控制侧"瞄旋转中心"档**（用拟合器的 C 或不跟板） | 5rad/s+ 主流方案本来就不跟板，且不依赖逐板 yaw |
| 4 | 拟合器：维持"自旋档 ω 观测源"，等前置问题解决后再评估收益 | — |

## 5. B 研究项（单独查，不接主链路）

**唯一要回答的问题**：

> 同一条自旋弧，**仿真干净数据拟合 1.54px**，**实车检测端点 17.8px** —— 差在哪？

已排除的嫌疑（都做过实验）：

* **运动模糊**：注入 60ms 模糊（等效 17.6px）反而把 rmse 降到 0.60px —— 匀速自旋的圆轨迹
  被平均后仍是圆弧（半径略小），慢层 R 直接吸收；
* **常量时间偏移**：纯相位误差（rmse 0.60–0.75px，ω 仍 ≈3.3）；
* **harness/内参/畸变/h 先验**：逐项查过，不是；
* **优化器起点**：用 EKF 的 θ0+ω 当起点，343 次拟合 rmse **逐位不变**。

剩下的两个嫌疑（都可离线查、都便宜）：

1. **检测关键点与刚体模型不自洽**：NN 的四个关键点 vs "灯条端点/板角"的定义差多少？随视角如何变？
   （能解释"静止好、自旋坏"：静止时只看一个视角，自旋时跑遍所有视角。）
2. **同窗口跨板**：5rad/s 时 90° 只要 0.31s，24 帧窗口必然跨板——分弧是否真的生效。

**判定方式**：把关键点定义差/跨板占比量出来，若能把自旋档拟合做到 ≤3px 占 30%+，
则 B 成立（拟合器值得回到主链路）；否则维持 A。

---

## 6. 一句话总结

**拟合器不是"6D 位姿估计器"，它是一个"自旋时的 ω 观测源"；它的收益上限由
"喂进去的观测能不能支撑刚体模型"决定（仿真 1.54px vs 实车 17.8px 就是这道坎）。
在跨过这道坎之前，主链路维持"PnP 位置 + EKF"，拟合器默认关闭。**

## 7. 实验记录：`yaw_refine`（spv `optimize_yaw` 的等价物）**三种种子都更差**（2026-10-12）

用户提出"板号逻辑正是 sp_vision 最擅长的"。查代码后确认它的机制是
`Solver::optimize_yaw`（`solver.cpp:204`）：**在 `gimbal_ypr[0]`（云台 yaw，来自 IMU）±70° 内
暴力搜重投影**。UV 有等价机制 `refineArmorYaw`，但 ① `tracker.yaml` 里 `yaw_refine: false`
（生产里是关的），② 它的搜索初值取 **PnP 解出的法向方位角** —— **从病态值出发搜**。

于是做了三组实验（同一份 det2.csv，四角点口径，中位 px）：

| 配置 | 斜视·静止（配对/最贴） | 正对·静止 | 自旋档 | 板心 |
|---|---|---|---|---|
| **基线**（`yaw_refine: false`） | 714.7 / **52.1** | **5.0** | **55.3** | **22.9** |
| `yaw_refine: true`，种子 = PnP 法向 | 715.9 / 49.7 | 5.4 | **109.1** | 38.5 |
| `yaw_refine: true`，种子 = **"板正对相机"**（无歧义先验，spv 云台先验的等价物） | 151.0 / **108.5** | 5.4 | **217.3** | **116.2**（cz 跑到 3.2m） |

**三种都更差，种子换成"无歧义"那版最差。** 结论不是"种子不对"，而是**这个机制本身在
UV 的当前状态下不成立**：

> `refineArmorYaw` 固定 PnP 的 `tvec`、只转方位角。当 PnP 的**位置/深度**本身就不好时，
> "精修之后的朝向"与"没修的位置"互相矛盾 → 喂给 EKF 的 armor_yaw 与位置打架 →
> 模型被拖走（cz 3.2m 就是这么来的）。

所以"spv 的板号能力"**不能靠打开等价开关搬过来**：在 UV 里 **位置与朝向是被一个坏 PnP
深度耦合在一起的**。要先把位置/深度（也就是识别层那条线：关键点定义、时间基、角点质量）
做对，yaw 精修才有意义 —— 这与本文 §4 的 A 工作面前两项是同一件事。

**本实验已整段回退**（`yaw_refine: false` 维持，新增的 `yaw_refine_seed` 选项也一并撤掉），
不留没收敛的路径。
