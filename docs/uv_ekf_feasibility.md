# UV-EKF + 刚体分解：可行性验证（分支 `uv`，2026-10-12 起）

> 方案来源：用户提供的《UV-EKF + 刚体分解方案》——不用局部拟合器，直接把
> **四个灯条端点的像素**当作 EKF 观测：差分信号（上下端点之差）更新旋转、平均信号
> 更新平移，从而在**观测层面**解耦。
>
> 本文记录**实测/实测代码**得到的结论，包括**对方案本身和对我自己上一轮修正的纠正**。

---

## 1. 机制可行性：**成立**（用我们已标定的常数实测）

| 量 | 值 | 来源 |
|---|---|---|
| 检测端点噪声 σ_corner | **0.67 px**（p90 1.37） | det2.csv 静止段同板逐帧位移/√2，n=1524 |
| 差分灵敏度 ∂(Δu)/∂θ | **0.413 px/度**（数值）／0.265（一阶解析式） | `uv_ekf_test` 里对同一模型做 1° 有限差分 |
| 单帧正面 yaw 噪声（单灯条 / 两灯条） | **1.6° / 1.1°** | σ_corner ÷ 灵敏度（两灯条按 √2） |
| 10 帧 EKF 累积 | **~0.5°** | ÷√10 |

结论：**差分信号确实能在正面提供 yaw，量级够用**（方案宣称的 2–4° 我们实测更乐观），
而且**不依赖任何优化器**（每帧一次 EKF 更新）。这与局部拟合器"自旋档 ≤3px 占比 0%"形成对比。

## 3. 两个**实测发现**（都对方案有影响）

### 3.0 补记（2026-10-12 晚）：两次"以为找到了"的排查，都要记下来
1. **"残差符号反了"是无效假设**：把 `(h−z)` 改成 `(z−h)` 后**输出逐位不变** ——
   因为雅可比是**对同一个函数做数值差分**，残差翻号雅可比同时翻号，`K·r` 不变。
   （这也说明：数值雅可比下，"残差符号约定"这类错误**不会**表现为方向反，只会表现为全局符号抵消。）
2. **阻尼步长不够**：给更新加增益 0.5 / 0.25 后，状态仍然收敛到**错的态**
   （真值 +5.73°，收敛到 179° / −76°）→ 不是"冲过头"这么简单。

### 3.1 单板下 **C 与 θ 近退化** —— 方案里的"先差分、再平均"是**必需的**（我上一轮的"修正"是错的）

第一版实现按"数学等价"把差分/平均合并成**一次 8 维更新**（把两者的噪声差异写进 R 的分块），
理由写在了 `uv_observation.hpp` 的注释里。**实测它在自洽的单板场景直接发散**：

```
真值 yaw = +5.73°
it=0  yaw=0.000°  r = [-42.1 -0.2  -44.1 -0.7  -42.7 +0.2  -44.6 +0.5]   ← 四个端点 u 都 -43px
      → yaw = -5.711°（**反方向**）  残差 30.7 → 61.3px → 随后爆掉（-169.7°）
```

原因：**对单块板，"绕旋转中心的 yaw 旋转"与"横向平移"在图像上几乎是同一个位移**
——两者雅可比列几乎平行（C↔θ 近退化）。一次更新会把这个位移按先验方差**劈**给两者，
于是一半修正跑到了错误的方向上。

→ **方案文档的"先差分、再平均"不是冗余，而是打破这个退化**：差分信号**与平移无关**，
先用它单独定 θ；再由平均信号在 θ 已知下定 C。**我上一轮"改成一次 8 维"的修正是错的**，
已把这段记录在案。

### 3.2 收敛盆很小 —— UV 观测**必须**由 PnP 初始化（与方案 §6.6 一致）

初值 yaw 差 12° 时，端点创新 ~500px，NIS 直接把更新全挡掉（不收敛）。所以：
* 初值/重捕必须由 PnP 给（方案 §6.6 已经这么建议）；
* 门限在"未收敛/刚重捕"时要放开（本项目 EKF 的 P 大时门限自动变宽，能覆盖一部分）。

## 4. 一个实打实的好处：**错关联只污染当帧**

测试里把板号故意错 180° → `updateUV` 返回 0（被 NIS 门限拒绝）✓。
这与局部拟合器形成鲜明对比：拟合器错关联会**污染一整段窗口**（24 帧的弧），
而 UV-EKF 是**逐帧观测**，错关联只丢一帧。
