# UV（像素重投影）观测加入 auto_aim

## 1. 要解决什么

现在 auto_aim 的量测是 **YPD**：先对装甲板四点跑一次 `solvePnP`，再把
`yaw / pitch / distance / armor_yaw` 当量测喂给 `ArmorEKF`。问题是：

* PnP 会把像素噪声**放大而且变得相关**，其中距离方向最病态（小靶面正对相机时，
  距离对像素误差的敏感度极高），而我们只能用一条对角线噪声去描述它
  （`configs/tracker.yaml` 里 `measure_noise` + `range_noise_distance_scale`
  就是在补这个偏差）；
* 于是"像素噪声 → 位姿噪声 → 状态噪声"中间多了一层非线性放大，误差来源不易追。

UV 观测把这一层去掉：**直接把四个角点像素放进滤波器**，观测函数写重投影
`pixel = K · R_world→camera · p_world(state)`，整条链只做一次最小二乘（EKF 自己），
量测噪声就是像素噪声（可标定、无相关）。

## 2. 实现（都在 `src/auto_aim/`）

| 位置 | 内容 |
|---|---|
| `Kalman/armor_ekf.hpp` | `UvCamera`（内参 + world→camera）、`UvObservation`（四角点 + 半尺寸 + σ）、`armorCornersOf()`（状态→四角点世界坐标）、`predictUvCorners()`（重投影）、`uvJacobian()`（**中心差分**雅可比）、`updateUvBatch()`（可批量、带 NIS 门限的 EKF 更新） |
| `Kalman/tracker.hpp/.cpp` | `setCameraIntrinsics()`、`uvCamera()`、`armorUvObservation()`；单板与多板两条更新路径都支持 UV（多板同帧 = 同一刚体、每多一块多 8 个约束） |
| `configs/tracker.yaml` | `uv_observation`（默认 **false**）、`uv_sigma_px`、`uv_nis_threshold`；板面尺寸**复用 `pnp` 段**，保证"重投影的模型"和"观测的角点"是同一个几何量 |
| `test/armor_ekf_uv_test.cpp` | 纯数学自检：投影自洽 + 1 px 噪声下收敛（位置/朝向/角速度） |
| `tools/auto_aim_sim_test.sh` | 仿真 A/B：起（或**附着到已在跑的**）仿真器 → 跑视觉端 → 用 `tools/truth_regression.py` 出逐级误差 |

两个实现细节值得记下来，都是踩过的坑：

1. **雅可比用中心差分**。状态只有 9 维、每块板 4 个角点，一次更新多算 ~72 次投影，
   相对 20 ms 的推理可以忽略；而手写 8×9 解析式（含 `[sinθ, cosθ]` 表示、板面切向、
   竖直方向）几乎一定会写错，错了还不报错、只是慢慢把状态带偏。
2. **矩形装甲板的四角存在镜像二义**（PnP 的 IPPE 同样有两个解：180° 绕法向旋转
   把左右、上下同时镜像）。UV 更新里按**重投影残差最小**在 4 种符号组合里选配对，
   与 IPPE 选解一个口径；这样 world 系的"上下/左右"符号不必靠猜。
   （实测：符号选错时残差 ≈ 30 px，NIS 门限会把这一帧全拒掉，滤波器不更新 →
   状态只能靠滑行 → 表现是"用了 UV 反而更差"。）

## 3. 实测

### 3.1 纯数学（`ctest -R armor_ekf_uv`）

1 px 角点噪声、每帧只有一块可见板、30 Hz：

```
uv ekf: centre 0.072 m, yaw 0.029 rad, omega 0.082 rad/s, residual 0.89 px
```

### 3.2 仿真：残差（`ULTRA_VISION_UV_DEBUG=1`）

静止/慢速时重投影残差 RMS **0.5~1.2 px**（与角点噪声一致 ✓）；
旋转中会出现 5~6 px（运动模糊 + 帧与位姿的时间差）。

### 3.3 仿真 A/B（`tools/auto_aim_sim_test.sh --uv 0|1`）

同一时长（25 s）先后各跑一次：

| 配置 | observation error（中位） | chassis center error（中位） |
|---|---|---|
| `uv_observation: false`（现状） | 0.072 m | **0.056 m** |
| `uv_observation: true` | 0.085 m | 0.103 m |
| `uv_observation: true, σ=4 px` | 0.100 m | 0.140 m |

**结论：暂时是 UV 更差，所以默认保持关闭。** 同时这条 A/B 目前**不干净**：
仿真每轮的重合（小陀螺）相位不同，`omega` 中位在 0.01~2.7 rad/s 之间跳，
而 `truth_regression.py` 的门限（0.05 / 0.06 m）是按静止场景定的；
`observation error` 那一列还受"哪块板被选中"影响（它记录的是被选中板的 PnP 输出），
所以不能当作纯 PnP 质量指标。要下结论必须先做**受控对比**。

## 4. 三个参考实现怎么用 UV（2026-09-26 读码 + 实测）

| 参考 | 观测形式 | 估计器 | 对我们的启发 |
|---|---|---|---|
| `jlu_vision_26-master`（最早做像素残差） | **每个角点一个重投影因子**（2 维） | GTSAM 因子图：每帧一块板的 Pose3 + 底盘中心/朝向/速度/几何参数，靠运动因子连成滑动窗口；雅可比走 `H_calib·H_norm·H_transform`（GTSAM 自带导数） | ①重投影要**和别的因子一起用**（中心/半径/朝向），不是单独拿像素；②他们特意把"中心→装甲板位移"分解成切向/径向，**半径只由径向项约束**，避免 yaw 误差通过切向残差把半径拉小；③多块板同帧要各自分配变量 |
| `rmcs_auto_aim_v2-main`（南理工） | **灯条两个端点像素**（4 维/灯条） | EKF，状态含几何（radius_forward/lateral、height_lateral）；**逐条观测更新**（每喂一条就用更新后的状态重新线性化）；Joseph 形式 + 对称化；状态夹到物理区间；无 NIS 硬门限 | ①顺序更新（我们照做）；②有效像素噪声 σ≈6.3 px（`noise_observation=40 px²`）——**按有效误差给**，不是按角点检测噪声；③关联用"最佳四角匹配当锚 + 按 x 排序递推"，并额外吃**孤立灯条**（观测比"完整装甲板"多） |
| `awakening-main` | **紧凑 UV**：`(angle, center_x, center_y, length)` 4 维（`points_to_observation`） | 误差状态 EKF + **Ceres Jet 自动微分**求雅可比 | ①灯条 4 维参数化：比"四角点 8 维"少一半、**没有角点配对二义**，三个量各自对应一个物理方向；②雅可比应该自动微分（我们暂时用中心差分，成本同量级但不如 AD 精确） |

同时保留 `sp_vision` 的工程做法：观测/关联/门限都在一个类里、启动打印配置、A/B 开关 + 实测数字写进注释。

**已按参考改的**：逐条顺序更新（南理工）、紧凑 UV（awakening）、Joseph + 对称化、按最小残差在多个关联假设里选一个、σ 改成有效误差（6 px / 0.05 rad）、以及新增"一步方向"单测。

**"一步方向"单测抓到的真 bug**：紧凑更新里"观测是左灯条还是右灯条"两个假设**都被 apply 了一遍** —— 正确假设刚把状态拉过去，错误假设又把它拽回来。观测偏 +12 px 时预测反而朝 **−44 px** 走。改成"只应用残差更小的那个假设"后，两条路径都是一步 +12.02 px ✓。这条单测与收敛速度、噪声大小都无关，是最锐利的判据，已保留在 `armor_ekf_uv_test` 里。

**板面尺寸的坑**：重投影模型的尺寸必须**匹配探测器的点语义**，不是"标准装甲板尺寸"。
实测（仿真，`ULTRA_VISION_UV_DEBUG=1` 看重投影残差中位）：
* 按标准 135×125 mm 重投影：残差中位 **66 px**，状态直接发散（中心误差 1.9 m）；
* 按 pnp 段标定的等效尺寸 134×57 mm（本工程针对 Daedalus 标定过，用来补偿轮廓中心/装甲板中心的定义差异）：静止时残差 **0.5~1.2 px** ✓。

## 5. 下一步（按优先级）

1. **关联/分支问题（现在的主要障碍）**：车体模型里四块板相隔 90°，yaw 与
   yaw+180° 的**重投影几乎一样**（镜像位姿），纯像素残差无法自己选对分支；而 YPD
   那边靠 PnP 的 `armor_yaw`（有方向的径向角）就能定住。实测：UV 路径在仿真里先
   收敛几步（残差 0.5 px）随后发散（中心误差 0.26~1.06 m），YPD 同场景 0.086 m。
   下一步按 jlu_vision 的做法把"重投影 + 朝向/半径因子"**一起**用（我先试了直接叠加
   `updateAngle`，反而更差 1.06 m —— 说明叠加的位置/权重不对，要在关联层解决，
   而不是把两个量测硬塞在同一个 EKF 更新里）。
2. **受控 A/B**：关掉仿真的小陀螺（或按 `truth_regression` 的逐帧输出只比较
   "静止段"），uv0/uv1 各跑 2~3 轮取中位；这才是能下结论的数据。
2. **时间一致性**：旋转中 5~6 px 的残差说明"帧曝光时刻 / 相机位姿时刻 / 状态推进时刻"
   之间有系统偏差（估计 10~30 ms）。YPD 路径对这个不敏感（角度量测），UV 路径直接吃
   像素误差 —— 要么把三者对齐（更正确），要么把 σ_px 写成"随角速度增长"。
3. **再谈"省掉 PnP"**：现在 PnP 只用于初始化/板号匹配/自适应（几微秒，不是瓶颈），
   UV 的价值在**误差来源干净**；等 1、2 做完再考虑把初始化也改成像素域
   （那才是真正的"少一次最小二乘"）。
