# 实拍（蓝灯条）验证结果 — 2026-10-09

## 结论（先说）

**`20261009092857691.mp4` 这段蓝灯条视频不能用来验证局部拟合器。**
不是算法的问题，是这段素材本身：**贴脸特写 + 转速快到 24fps 的采样极限**，
四块几乎一模一样的装甲板在帧间无法保持身份，单板灯条轨迹拿不到，拟合自然不收敛。

下面全部是可复现的实测数字，命令见文末。

## 2. 转速：≈12 rad/s（正好踩在采样极限上）

"最正对的那块装甲板"的灯条分离 `sep(t)` 是一条干净的三角波（`data/real/blue_omega_diag.png`）：

- 峰值间隔中位 **3.0 帧**，全程 351 帧都稳定；
- `sep` 在 **160 ~ 240 px** 之间振荡，最小/最大 = **0.66**（板扫到 ±45° 时理论上应降到 cos45°=0.707，吻合）；
- 90° / 3 帧 = **30°/帧 → ω ≈ 12.6 rad/s**（≈2 转/秒）。

⚠️ 3 帧周期**恰好是 24fps 的 Nyquist 周期**，所以真值还有 ±aliasing 歧义
（也可能是 60°/帧 → 25 rad/s，或视频是被加速导出的）。无论取哪个解，都远超
比赛常态 **1.5~3 rad/s**，也超过本工程自己定义的"极端档" 5 rad/s。
这段素材是**把车当陀螺拧**（字幕"停止小陀螺"），不是比赛工况。

## 3. 为什么单板轨迹拟合失败

30°/帧的角步 + 四块板互成 90° + 四块外观几乎相同（都是"3"）：

- "同一块板"与"下一块板"在像素上只差约 1/3 个运动周期，最近邻关联必然串板；
- 实测：全检测导出 + 带门限的连续跟踪，最长轨迹 31 帧，但把该轨迹端点画出来
  **散布在整幅图像**（u 从 100 到 800），说明它每 3~4 帧就跳到另一块板；
- 把该轨迹喂给 `SpinGeometryEstimator`：`valid=0`，**重投影 RMSE 66 px**（灯条本身才 125 px），
  灯条倾角 α 跑到边界 **83°**。→ 这个拟合没有任何意义。

对照：红车那段 `VID_20261009_093055.mp4` 实测转速约 **4.7 rad/s**，
同样串板（重投影 20~28 px / 灯条仅 90 px，`valid=0`），也不可用。

## 5. 要验证 α / L / R 与局部拟合器，重拍要求

1. **转速 1.5~3 rad/s**（比赛常态），最高别超 5；
2. **帧率 ≥60 fps**（30°/帧在 24fps 已经贴着 Nyquist；60fps 下 12 rad/s 也只有 12°/帧）；
3. 整台车完整入画，**距离 1.5~3 m**（这段 0.3 m 太近，边缘透视 + 遮挡都严重）；
4. 相机固定（这段做得很好，保持）；
5. 若能给原始未降帧文件更好；导出时不要变速。
